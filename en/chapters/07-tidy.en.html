7  Tidy data

Lesson goals

By the end of this lesson you will be able to:

  1. Recognise whether a table is tidy and identify what keeps it from being so.
  2. Convert tables from wide to long (pivot_longer) and from long to wide (pivot_wider).
  3. Split and join columns (separate_wider_delim, unite).
  4. Make implicit missing values explicit (complete) and handle missing values (drop_na, replace_na, fill).
  5. Choose the right format for each step: models and plots want long data; genotype × environment matrices want wide data.

7.1 What tidy data is

The same data can be organised in many ways. Here are three versions of the mean yield (t/ha) of two hybrids at two locations:

# Version A: one column per location
tribble(
  ~hybrid, ~vicosa, ~londrina,
  "HB01",  8.9,     9.5,
  "HB02",  8.2,     8.8
)
#> # A tibble: 2 × 3
#>   hybrid vicosa londrina
#>   <chr>   <dbl>    <dbl>
#> 1 HB01      8.9      9.5
#> 2 HB02      8.2      8.8

# Version B: one row per hybrid and location
tribble(
  ~hybrid, ~location,  ~yield_t_ha,
  "HB01",  "vicosa",   8.9,
  "HB01",  "londrina", 9.5,
  "HB02",  "vicosa",   8.2,
  "HB02",  "londrina", 8.8
)
#> # A tibble: 4 × 3
#>   hybrid location yield_t_ha
#>   <chr>  <chr>         <dbl>
#> 1 HB01   vicosa          8.9
#> 2 HB01   londrina        9.5
#> 3 HB02   vicosa          8.2
#> 4 HB02   londrina        8.8

# Version C: hybrid and location glued into one column
tribble(
  ~plot,            ~yield_t_ha,
  "HB01_vicosa",    8.9,
  "HB01_londrina",  9.5,
  "HB02_vicosa",    8.2,
  "HB02_londrina",  8.8
)
#> # A tibble: 4 × 2
#>   plot          yield_t_ha
#>   <chr>              <dbl>
#> 1 HB01_vicosa          8.9
#> 2 HB01_londrina        9.5
#> 3 HB02_vicosa          8.2
#> 4 HB02_londrina        8.8

All three hold exactly the same information, but only version B is tidy. A table is tidy when it follows three rules:

  1. Each variable is a column. In version A, “location” is a variable, but it is spread across the column names. In version C, two variables (hybrid and location) share the same column.
  2. Each observation is a row. Here, the unit of observation is “one hybrid at one location”.
  3. Each value is a cell.

Why does this matter? Because every tidyverse tool expects this format. With version B, filtering a location, computing the mean per hybrid, fitting lm(yield_t_ha ~ hybrid + location) or drawing a plot with one colour per location are direct operations. With version A, each one needs a different workaround.

TipWhat counts as “a variable” depends on the question

In a trial with yield, height and flowering, each trait is usually a column (an observation is a plot). But if the question is “what is the coefficient of variation of each trait at each location?”, it is more convenient to have a trait column and a value column. Moving from one format to the other is the core skill of this lesson.

NotePackage intent: tidyr

Problem it solves. Spreadsheets are laid out for human reading or for typing in the field, hardly ever for analysis: columns per year, per location or per replicate, compound identifiers, merged cells and missing combinations.

Philosophy. tidyr has a single goal: change the shape of a table without changing its information. Its functions come in small, symmetric families: pivot_longer/pivot_wider (lengthen and widen), separate_wider_*/unite (split and join columns), complete/drop_na/fill/replace_na (deal with missing values) and nest/unnest (tables inside tables).

Why this one and not the alternatives. Base R’s old reshape() and reshape2’s melt()/cast() solve the same problem with less clear interfaces; tidyr itself replaced its gather() and spread() with the easier-to-remember pivot_*(). You will still see gather()/spread() in older code; they work, but do not use them in new code.

  • cols: which columns will be “melted”;
  • names_to: the name of the new column that receives those columns’ names;
  • values_to: the name of the new column that receives their values.
maize_2025 <- maize_2025_wide |>
  pivot_longer(
    cols = starts_with("prod_"),
    names_to = "local",
    values_to = "prod_kg_ha"
  )

We went from 60 rows and 6 columns to 240 rows and 4 columns. The local (location) column kept the prod_ prefix; the names_prefix argument removes it:

maize_2025 <- maize_2025_wide |>
  pivot_longer(
    cols = starts_with("prod_"),
    names_to = "local",
    names_prefix = "prod_",
    values_to = "prod_kg_ha"

7.2.1 Joining the two seasons

Both seasons now have the same structure, but the locations are written differently: "Viçosa" in the 2024 spreadsheet (the sheet name) and "vicosa" in the 2025 file (a code). The locais.csv file holds the mapping between the code and the municipality name:

locations <- read_csv(here("data", "raw", "locais.csv"), show_col_types = FALSE)
locations |> select(local, municipio)
#> # A tibble: 4 × 2
#>   local       municipio  
#>   <chr>       <chr>      
#> 1 vicosa      Viçosa     
#> 2 sete_lagoas Sete Lagoas
#> 3 rio_verde   Rio Verde  
#> 4 londrina    Londrina

We use this table to replace the code with the name. The left_join() function is the topic of lesson 10; for now, it is enough to know that it brings the columns of locations into the rows of maize_2025 with the same local:

maize_2025 <- maize_2025 |>
  left_join(select(locations, local, municipio), by = "local") |>
  mutate(local = municipio, safra = "2024/25", .keep = "unused")

7.2.2 Several traits at once

  pivot_wider(names_from = local, values_from = mean)

7.4 Splitting and joining columns

Compound identifiers are common in field sheets and genotyping files, such as "HB01-B2" for hybrid HB01 in block 2. unite() creates this kind of code and separate_wider_delim() undoes it:

plots <- maize_2024 |>
  select(local, hibrido, bloco, prod_kg_ha) |>
  unite("plot", hibrido, bloco, sep = "-B")

plots
#> # A tibble: 240 × 3
#>    local    plot    prod_kg_ha
#>    <chr>    <chr>        <dbl>
#>  1 Londrina HB01-B1       9779
#>  2 Londrina HB01-B2       9706
#>  3 Londrina HB01-B3       9039
#>  4 Londrina HB02-B1       8403
#>  5 Londrina HB02-B2       9430
#>  6 Londrina HB02-B3       8495
#>  7 Londrina HB03-B1      10545
#>  8 Londrina HB03-B2       9140
#>  9 Londrina HB03-B3         NA
#> 10 Londrina HB04-B1       7848
#> # ℹ 230 more rows

plots |>
  separate_wider_delim(plot, delim = "-B", names = c("hibrido", "bloco"))
#> # A tibble: 240 × 4
#>    local    hibrido bloco prod_kg_ha
#>    <chr>    <chr>   <chr>      <dbl>
#>  1 Londrina HB01    1           9779
#>  2 Londrina HB01    2           9706
#>  3 Londrina HB01    3           9039
#>  4 Londrina HB02    1           8403
#>  5 Londrina HB02    2           9430
#>  6 Londrina HB02    3           8495
#>  7 Londrina HB03    1          10545
#>  8 Londrina HB03    2           9140
#>  9 Londrina HB03    3             NA
#> 10 Londrina HB04    1           7848
#> # ℹ 230 more rows

Notice that bloco came back as text (<chr>): splitting columns always produces text. Convert it with mutate(bloco = as.integer(bloco)) when you need the number.

When the parts have a fixed width, separate_wider_position() cuts by position:

tibble(code = c("MG2023HB01", "GO2024HB15")) |>
  separate_wider_position(code, widths = c(state = 2, year = 4, hybrid = 4))
#> # A tibble: 2 × 3
#>   state year  hybrid
#>   <chr> <chr> <chr> 
#> 1 MG    2023  HB01  
#> 2 GO    2024  HB15

For more complex patterns there is separate_wider_regex(), which uses regular expressions (lesson 8).

7.5 Missing values: explicit and implicit

A value can be missing in two ways:

  • explicitly: the row exists, but the cell is NA;
  • implicitly: the row simply does not exist.
# Simulate a file in which whoever typed it deleted the lost plots
maize_no_lost <- maize_2024 |>
  filter(!is.na(prod_kg_ha)) |>
  select(local, hibrido, bloco, prod_kg_ha)

nrow(maize_no_lost)
#> [1] 233

Rows are missing, but nothing in the table says which. complete() creates every combination of the given variables, filling with NA those that did not exist:

maize_complete <- maize_no_lost |>
  complete(local, hibrido, bloco)

nrow(maize_complete)
#> [1] 240
maize_complete |> filter(is.na(prod_kg_ha))
#> # A tibble: 7 × 4
#>   local       hibrido bloco prod_kg_ha
#>   <chr>       <chr>   <dbl>      <dbl>
#> 1 Londrina    HB03        3         NA
#> 2 Londrina    HB06        3         NA
#> 3 Londrina    HB14        3         NA
#> 4 Londrina    HB17        2         NA
#> 5 Londrina    HB20        1         NA
#> 6 Sete Lagoas HB01        1         NA
#> 7 Sete Lagoas HB10        1         NA

Making missing values explicit matters before analyses that assume a balanced design, and to document what was lost.

The other missing-value functions:

# drop_na(): removes rows with NA (in every column, or only in the ones given)
maize_complete |> drop_na(prod_kg_ha) |> nrow()
#> [1] 233

# replace_na(): replaces NA with a value (careful: zero is not the same as "not measured"!)
maize_2024 |> replace_na(list(obs = "no note")) |> count(obs)
#> # A tibble: 3 × 2
#>   obs                 n
#>   <chr>           <int>
#> 1 acamamento         11
#> 2 no note           222
#> 3 parcela perdida     7

# fill(): repeats the last non-missing value, common in spreadsheets where the
# hybrid name is only written on the first row of each group
tribble(
  ~hybrid, ~block, ~yield,
  "HB01",  1,      9.1,
  NA,      2,      8.7,
  NA,      3,      9.4,
  "HB02",  1,      8.2,
  NA,      2,      8.5
) |>
  fill(hybrid)
#> # A tibble: 5 × 3
#>   hybrid block yield
#>   <chr>  <dbl> <dbl>
#> 1 HB01       1   9.1
#> 2 HB01       2   8.7
#> 3 HB01       3   9.4
#> 4 HB02       1   8.2
#> 5 HB02       2   8.5

7.6 Preview: tables inside tables

tidyr lets you store a whole table in each cell of a column, with nest():

maize_2024 |>
  nest(data = -local)
#> # A tibble: 4 × 2
#>   local       data             
#>   <chr>       <list>           
#> 1 Londrina    <tibble [60 × 8]>
#> 2 Rio Verde   <tibble [60 × 8]>
#> 3 Sete Lagoas <tibble [60 × 8]>
#> 4 Viçosa      <tibble [60 × 8]>

Each row is a location, and the data column holds that location’s 60 plots. It looks odd now, but combined with purrr this format lets you fit one model per environment in three lines. It is the topic of lesson 15.

7.7 Under the hood

7.7.1 The format depends on the tool

Tool Expected format
dplyr, ggplot2, lm(), lme4, asreml long (tidy)
cor(), prcomp(), matrix algebra, marker matrices wide (matrix)
reports and spreadsheets for people usually wide

That is why both pivot directions matter equally: data are stored tidy and widened only when a tool requires it.

7.7.2 What pivot_longer() does, step by step

pivot_longer() internally builds a specification stating, for each original column, which value it will have in the new names column. You can look at it and even edit it:

build_longer_spec(
  maize_2025_wide,
  cols = starts_with("prod_"),
  names_to = "local",
  names_prefix = "prod_",
  values_to = "prod_kg_ha"
)
#> # A tibble: 4 × 3
#>   .name            .value     local      
#>   <chr>            <chr>      <chr>      
#> 1 prod_vicosa      prod_kg_ha vicosa     
#> 2 prod_sete_lagoas prod_kg_ha sete_lagoas
#> 3 prod_rio_verde   prod_kg_ha rio_verde  
#> 4 prod_londrina    prod_kg_ha londrina

For tricky cases (for example columns such as yield_2023, yield_2024, ht_2023, ht_2024), names_to accepts the special marker ".value", which keeps part of the name as a column:

tibble(hybrid = c("HB01", "HB02"),
       yield_2023 = c(9.1, 8.4), yield_2024 = c(9.6, 8.1),
       ht_2023 = c(220, 215),    ht_2024 = c(228, 211)) |>
  pivot_longer(-hybrid, names_to = c(".value", "year"), names_sep = "_")
#> # A tibble: 4 × 4
#>   hybrid year  yield    ht
#>   <chr>  <chr> <dbl> <dbl>
#> 1 HB01   2023    9.1   220
#> 2 HB01   2024    9.6   228
#> 3 HB02   2023    8.4   215
#> 4 HB02   2024    8.1   211

7.8 Exercises

  1. Tidy or not? For each table, say whether it is tidy and, if not, which rule it breaks: (a) a spreadsheet with columns hybrid, rep1, rep2, rep3 holding the yield of each replicate; (b) a table with columns hybrid, trait, value; (c) a location_year column with values such as "vicosa_2024".
TipSolution

  1. No: “replicate” is a variable spread across the column names (breaks rule 1). Use pivot_longer(starts_with("rep"), names_to = "rep", names_prefix = "rep").

  2. It depends on the question. If the observation is “one trait measured on one hybrid”, it is tidy; if the analysis treats each trait as a variable (for example, the correlation between yield and height), you need to widen it with pivot_wider().

  3. No: two variables in one column (breaks rule 1). Use separate_wider_delim(location_year, "_", names = c("location", "year")).

  1. Lengthen. The table below holds plant height at three assessment dates. Put it in long format, with a numeric days_after_sowing column.
heights <- tribble(
  ~hybrid, ~das_30, ~das_60, ~das_90,

  "HB02",  41,      122,     205,
  "HB03",  48,      138,     231
)

heights |>
  pivot_longer(
    cols = starts_with("das_"),

names_transform converts the names column, which would be text, into a number.

  1. Widen. From maize (both seasons), build a table with one row per hybrid and one column for each combination of location and season, holding the mean yield. How many columns does it have?
TipSolution 
maize |>
  summarise(mean = mean(prod_kg_ha, na.rm = TRUE), .by = c(hibrido, local, safra)) |>

#> [1] 9

One hybrid column plus 4 locations × 2 seasons = 9 columns. When names_from has two columns, the names are joined with _.

Summary

  • Tidy data: each variable in a column, each observation in a row, each value in a cell.
  • pivot_longer() turns columns into rows (cols, names_to, values_to, names_prefix); pivot_wider() does the reverse (names_from, values_from).
  • Store data in long format and widen only when a tool demands it, as with the genotype × environment matrix.
  • separate_wider_delim() and unite() undo and create compound identifiers.
  • complete() makes implicit missing values explicit; drop_na(), replace_na() and fill() handle missing values deliberately.
