Lesson goals

By the end of this lesson you will be able to:

  1. Pick rows (filter) and columns (select) from a table with clear conditions.
  2. Create and modify columns (mutate), including classifications into ranges (case_when).
  3. Sort (arrange) and summarise (summarise) data.
  4. Do any operation by group (location, hybrid, block) with .by or group_by().
  5. Chain everything with the pipe to answer real questions about a multi-environment trial.

6.2 The dplyr grammar

NotePackage intent: dplyr

Problem it solves. Manipulating tables in base R means combining [, $, subset(), aggregate(), tapply() and order(), each with its own logic. The resulting code is hard to read and to change.

Philosophy. dplyr offers a small set of verbs, each with a single responsibility, that take a table as their first argument and return a table. Inside the verbs, columns are referred to by name, without quotes and without $. Combined with the pipe, the verbs form sentences that read like a description of the analysis: “take the trial, keep Londrina, group by hybrid, summarise yield”.

Why this one and not the alternatives. Base R can do everything, but with more reading effort. data.table is faster and more concise, at the cost of a denser syntax; we will meet it in lesson 18. dplyr also works as an interface to databases and to duckdb, so the same code serves tables that do not fit in memory.

The verbs we will see today:

Verb Acts on What it does
filter() rows keeps rows that meet conditions
select() columns picks, drops or renames columns
mutate() columns creates or modifies columns
arrange() rows sorts rows
summarise() groups reduces each group to one summary row

They all follow the same rules: the first argument is the table, the following ones describe what to do using column names, and the result is always a new table. The original table is never modified; to keep the result, assign it to an object.

6.5.1 Classifications: if_else() and case_when()

For two categories, if_else(condition, value_if_true, value_if_false):

maize |>
  mutate(lost = if_else(is.na(prod_kg_ha), "yes", "no")) |>
  count(lost)
#> # A tibble: 2 × 2
#>   lost      n
#>   <chr> <int>
#> 1 no      233
#> 2 yes       7

For several ranges, case_when() evaluates the conditions in order and uses the first true one:

maize <- maize |>
  mutate(
    cycle = case_when(
      florescimento_dias <= 60 ~ "early",
      florescimento_dias <= 64 ~ "medium",
      florescimento_dias > 64  ~ "late",
      .default = NA_character_
    )
  )

count(maize, cycle)
#> # A tibble: 3 × 2
#>   cycle      n
#>   <chr>  <int>
#> 1 early     56
#> 2 late      77
#> 3 medium   107

Because the conditions are evaluated in order, the second one (<= 64) only reaches those that did not match the first, that is, 61 to 64 days. .default sets the value when no condition is true.

Notice that this time we stored the result in maize: the cycle column will be available for the rest of the lesson.

maize |>
  summarise(

    mean_kg_ha = mean(prod_kg_ha, na.rm = TRUE),

6.8 Grouped operations

The .by argument makes any verb operate separately in each group:

maize |>
  summarise(
    n = n(),
    mean_kg_ha = mean(prod_kg_ha, na.rm = TRUE),
    cv_pct = 100 * sd(prod_kg_ha, na.rm = TRUE) / mean_kg_ha,
    .by = local
  )
#> # A tibble: 4 × 4
#>   local           n mean_kg_ha cv_pct
#>   <chr>       <int>      <dbl>  <dbl>
#> 1 Londrina       60      9194.  11.7 
#> 2 Rio Verde      60     10295.  10.1 
#> 3 Sete Lagoas    60      9532.   9.33

6.8.1 group_by(): the traditional form

You will see a lot of code with group_by() followed by summarise(). The result is the same:

maize |>
  group_by(local) |>
  summarise(mean_kg_ha = mean(prod_kg_ha, na.rm = TRUE))
#> # A tibble: 4 × 2
#>   local       mean_kg_ha
#>   <chr>            <dbl>
#> 1 Londrina         9194.
#> 2 Rio Verde       10295.
#> 3 Sete Lagoas      9532.
#> 4 Viçosa           8816.

The difference is that group_by() creates a grouped table, which stays grouped in the following steps until you call ungroup(). That is useful in long chains, but a source of bugs when you forget the active grouping. The lab standard is .by for one-off operations and group_by() only when several consecutive steps use the same grouping.

6.8.2 Grouped mutate(): relative performance

In multi-environment trials, comparing raw yields across locations mixes the hybrid effect with the environment effect. A first step is to express each plot relative to the mean of its own location:

maize |>
  mutate(
    location_mean = mean(prod_kg_ha, na.rm = TRUE),
    deviation = prod_kg_ha - location_mean,
    relative_pct = 100 * prod_kg_ha / location_mean,
    .by = local
  ) |>
  select(local, hibrido, bloco, prod_kg_ha, location_mean, relative_pct) |>
  arrange(desc(relative_pct))

6.10 Case study: ranking the hybrids

Question: which hybrids had the best average performance across the four locations, and were they consistent, or did they shine in a single environment?

ranking <- maize |>
  # 1. mean of each hybrid at each location
  summarise(mean_kg_ha = mean(prod_kg_ha, na.rm = TRUE), .by = c(local, hibrido)) |>
  # 2. rank of each hybrid within each location (1 = best)
  mutate(rank = min_rank(desc(mean_kg_ha)), .by = local) |>
  # 3. summary per hybrid across the four locations
  summarise(
    overall_mean_kg_ha = mean(mean_kg_ha),
    best_rank = min(rank),
    worst_rank = max(rank),
    times_in_top5 = sum(rank <= 5),
    .by = hibrido
  ) |>
  arrange(desc(overall_mean_kg_ha))

6.11 Under the hood

6.11.1 Why dplyr understands unquoted names

In filter(maize, prod_kg_ha > 9000), prod_kg_ha is not an object in the global environment:

prod_kg_ha
#> Error:
#> ! object 'prod_kg_ha' not found

dplyr looks names up first among the table’s columns and only then in the environment. This mechanism, called data masking, is what makes the code so readable. It has one consequence: if a column and an object share a name, the column wins. To use the object, mark it with .env$:

threshold <- 10000
maize |> filter(prod_kg_ha > threshold) |> nrow()
#> [1] 69

prod_kg_ha <- 0   # an object with the same name as a column
maize |> filter(prod_kg_ha > .env$prod_kg_ha) |> nrow()   # compares with the object (0): all non-lost plots
#> [1] 233
rm(prod_kg_ha)

In lesson 16 we will see how to write functions that use dplyr, where this mechanism needs some extra care.

6.11.2 What a grouped table is

grouped <- group_by(maize, local)
class(grouped)
#> [1] "grouped_df" "tbl_df"     "tbl"        "data.frame"
group_vars(grouped)
#> [1] "local"
n_groups(grouped)
#> [1] 4

A grouped_df is a tibble with an extra attribute recording which rows belong to each group. The printout shows # Groups: local [4]; keep an eye on that line.

TipSolution

It removes the lost plots, converts yield to t/ha, computes for each hybrid at each location the difference between its best and worst block, sorts from the largest to the smallest difference and shows the first five. The question is: in which hybrid-location combinations were the blocks most discrepant? Very large values point to field heterogeneity or typing errors, and deserve to be checked before any analysis.

Summary

  • dplyr verbs take a table, use unquoted column names and return a new table.
  • filter() picks rows and drops NA in conditions; select() picks columns with helpers such as starts_with() and where().
  • mutate() creates columns; case_when() classifies into ranges, evaluating conditions in order.
  • arrange() sorts; summarise() reduces to a summary.
  • .by applies any verb by group: summarise() returns one row per group, mutate() keeps every row.
