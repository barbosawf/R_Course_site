Lesson goals

By the end of this lesson you will be able to:

  1. Read CSV files, including the Brazilian convention (; as separator, decimal comma, latin1 accents).
  2. Read Excel spreadsheets with several sheets, note rows and “dirty” cells.
  3. Control the type of each column and diagnose reading failures with problems().
  4. Standardise column names with janitor::clean_names().
  5. Read files from other statistical software and save results in suitable formats.

5.2 readr: reading text files

NotePackage intent: readr

Problem it solves. Base R’s reading functions (read.csv(), read.table()) are slow on large files, guess types in an opaque way, change column names without warning and, in older R versions, turned all text into factors.

Philosophy. readr reads the file, shows what it guessed about each column and returns a tibble. If a value does not fit the expected type, it neither stops nor hides it: it marks the value as NA and records what happened in problems(). Regional settings (decimal mark, encoding, date format) are gathered in a single object, locale().

Why this one and not the alternatives. read.csv() works and you will see it a lot, but it requires more care with types and names. data.table::fread() is even faster and will be covered in lesson 18, together with arrow for large files. For everyday trial data, readr strikes the best balance of speed, transparency and integration with the rest of the tidyverse.

Let us start with the simplest file:

locais <- read_csv(here("data", "raw", "locais.csv"))
#> Rows: 4 Columns: 6
#> ── Column specification ────────────────────────────────────────────────────────
#> Delimiter: ","
#> chr (3): local, municipio, uf
#> dbl (3): latitude, longitude, altitude_m
#> 
#> ℹ Use `spec()` to retrieve the full column specification for this data.
#> ℹ Specify the column types or set `show_col_types = FALSE` to quiet this message.
locais
#> # A tibble: 4 × 6
#>   local       municipio   uf    latitude longitude altitude_m
#>   <chr>       <chr>       <chr>    <dbl>     <dbl>      <dbl>
#> 1 vicosa      Viçosa      MG       -20.8     -42.9        650
#> 2 sete_lagoas Sete Lagoas MG       -19.5     -44.2        730

The Column specification message shows what readr concluded: local, municipio and uf (state) are text (chr); latitude, longitude and altitude_m are numbers (dbl). That conclusion comes from reading the first 1000 rows.

5.2.1 Specifying the types

In production scripts it is better to state the types than to let them be guessed. That way, if the file changes, you find out at reading time rather than three steps later:

locais <- read_csv(
  here("data", "raw", "locais.csv"),
  col_types = cols(
    local = col_character(),
    municipio = col_character(),
    uf = col_factor(),
    altitude_m = col_integer(),
    .default = col_double()
  )
)
locais
#> # A tibble: 4 × 6
#>   local       municipio   uf    latitude longitude altitude_m
#>   <chr>       <chr>       <fct>    <dbl>     <dbl>      <int>
#> 1 vicosa      Viçosa      MG       -20.8     -42.9        650
#> 2 sete_lagoas Sete Lagoas MG       -19.5     -44.2        730
#> 3 rio_verde   Rio Verde   GO       -17.8     -50.9        750
#> 4 londrina    Londrina    PR       -23.3     -51.2        585

The most used col_*() functions:

Function Type Shorthand in col_types = "..."
col_character() text c
col_double() decimal d
col_integer() integer i
col_logical() logical l
col_factor() factor f
col_date(format = ) date D
col_skip() skip the column _

For small tables the shorthand is handy: col_types = "ccfiddd" would say the same as the block above, column by column.

5.3 The “Brazilian-style” CSV

Spreadsheets exported from computers set up in Portuguese (and many other languages) usually use a semicolon as separator (because the comma is already the decimal mark) and often the latin1 encoding (ISO-8859-1) instead of UTF-8. Let us see what happens when we read the soybean trial naively:

soy_wrong <- read_csv(here("data", "raw", "soja_ensaio_2025.csv"), show_col_types = FALSE)
#> Warning: One or more parsing issues, call `problems()` on your data frame for details,
#> e.g.:
#>   dat <- vroom(...)
#>   problems(dat)
dim(soy_wrong)
#> [1] 120   1
names(soy_wrong)
#> [1] "Local;Cultivar;Bloco;Produtividade (sc/ha);Peso 100 sementes (g);Dias at\xe9 matura\xe7\xe3o;Acamamento;Data de semeadura"

A table with a single column, whose name is the whole header line. read_csv() looked for commas to split the columns, but the file uses ;. The accents also show up as \xe7, a sign of the wrong encoding.

5.3.1 Step one: separator and decimal mark

read_delim() accepts any separator, and locale() states the numeric convention:

soy <- read_delim(
  here("data", "raw", "soja_ensaio_2025.csv"),
  delim = ";",
  locale = locale(decimal_mark = ","),
  show_col_types = FALSE
)
soy |> select(Bloco, `Produtividade (sc/ha)`, `Peso 100 sementes (g)`) |> head(3)
#> # A tibble: 3 × 3
#>   Bloco `Produtividade (sc/ha)` `Peso 100 sementes (g)`
#>   <dbl>                   <dbl>                   <dbl>
#> 1     1                    56.1                    12.7
#> 2     2                    59.1                    15.8
#> 3     3                    55.5                    15.5
unique(soy$Local)
#> [1] "Vi\xe7osa" "Rio Verde"

The columns are split and the decimals are right (56.1, not 561), but “Viçosa” still shows up as "Vi\xe7osa". We used show_col_types = FALSE and printed only a few columns because, with the wrong encoding, R cannot even print the whole table: the accented names break printing with an invalid multibyte string error, another symptom of the same problem.

5.3.2 Step two: the encoding

An encoding is the table that translates bytes into letters. In UTF-8, “ç” takes two bytes; in latin1, one. Reading a latin1 file as if it were UTF-8 produces those odd characters. When you do not know the encoding, readr can estimate it:

guess_encoding(here("data", "raw", "soja_ensaio_2025.csv"))
#> # A tibble: 1 × 2
#>   encoding   confidence
#>   <chr>           <dbl>
#> 1 ISO-8859-1        0.4

We state the encoding in the same locale():

soy <- read_delim(
  here("data", "raw", "soja_ensaio_2025.csv"),
  delim = ";",
  locale = locale(decimal_mark = ",", encoding = "latin1")
)
#> Rows: 120 Columns: 8

#> Delimiter: ";"
#> chr (4): Local, Cultivar, Acamamento, Data de semeadura

TipShortcut: read_csv2()

read_csv2() already assumes ; as separator and a decimal comma. For this file, read_csv2(file, locale = locale(encoding = "latin1")) would give the same result. We prefer read_delim() in the text because it makes every decision explicit.

5.3.3 When reading fails: problems()

The Data de semeadura (sowing date) column was read as text. Let us ask for it to be read as a date in the Brazilian format (day/month/year):

soy_dates <- read_delim(
  here("data", "raw", "soja_ensaio_2025.csv"),
  delim = ";",
  locale = locale(decimal_mark = ",", encoding = "latin1"),
  col_types = cols(`Data de semeadura` = col_date(format = "%d/%m/%Y"))
)
#> Warning: One or more parsing issues, call `problems()` on your data frame for details,
#> e.g.:
#>   dat <- vroom(...)
#>   problems(dat)

The warning says there were problems. Instead of ignoring it, investigate:

problems(soy_dates) |> select(-file)
#> # A tibble: 23 × 4
#>      row   col expected           actual    
#>    <int> <int> <chr>              <chr>     
#>  1     2     8 date like %d/%m/%Y 2024-10-16
#>  2     8     8 date like %d/%m/%Y 2024-10-15
#>  3    10     8 date like %d/%m/%Y 2024-10-17
#>  4    12     8 date like %d/%m/%Y 2024-10-15
#>  5    30     8 date like %d/%m/%Y 2024-10-16
#>  6    32     8 date like %d/%m/%Y 2024-10-15
#>  7    34     8 date like %d/%m/%Y 2024-10-16
#>  8    43     8 date like %d/%m/%Y 2024-10-15
#>  9    44     8 date like %d/%m/%Y 2024-10-16
#> 10    46     8 date like %d/%m/%Y 2024-10-15
#> # ℹ 13 more rows

Some dates were typed in the international format (2024-10-16) and do not fit %d/%m/%Y. readr turned them into NA. Had you not looked at problems(), you would have lost those dates without noticing. In lesson 8 we will see how to read dates in mixed formats with lubridate; for now, the lesson is: every reading warning deserves a look at problems().

5.3.4 Coded missing values

By default, readr treats empty cells and the text "NA" as missing. If the spreadsheet uses other codes, list them in the na argument:

read_csv(file, na = c("", "NA", "-", "n/a", "lost"))

5.4 readxl: Excel spreadsheets

NotePackage intent: readxl

Problem it solves. Much field data arrives as .xlsx, often with several sheets, decorative headers and merged cells. Converting each sheet to CSV by hand is slow and leaves no record.

Philosophy. readxl reads .xls and .xlsx without depending on Excel or Java, following readr’s logic: it guesses types, accepts na and col_types and returns a tibble. It only reads, never writes, and does that well.

Why this one and not the alternatives. openxlsx and writexl also read or write Excel; openxlsx is great when you need to create formatted spreadsheets, and we used it to generate this course’s data. For reading, readxl is the simplest and most robust, and it is installed with the tidyverse. Old Java-based packages (xlsx, XLConnect) cause installation problems and should be avoided.

library(readxl)

maize_file <- here("data", "raw", "milho_met_2024.xlsx")
excel_sheets(maize_file)
#> [1] "Londrina"    "Rio Verde"   "Sete Lagoas" "Viçosa"

5.5 janitor: clean column names

Names like `Prod (kg/ha)` and `Data Plantio` need backticks in code, are easy to mistype and break the lab style.

NotePackage intent: janitor

Problem it solves. Data coming from spreadsheets have column names with spaces, accents, parentheses, capitals and duplicates, as well as empty rows and columns and totals mixed in with the data.

Philosophy. janitor gathers small “cleaning” functions that each do one thing and fit into the pipe. The most used one, clean_names(), converts every name to snake_case, strips accents and symbols and resolves repeated names.

Why this one and not the alternatives. Renaming column by column with dplyr::rename() works, but it is laborious and must be redone whenever the spreadsheet changes. clean_names() applies a consistent rule to any spreadsheet, in one line. janitor also offers remove_empty(), get_dupes() and tabyl(), which we will use throughout the course.

library(janitor)
#> 
#> Attaching package: 'janitor'
#> The following objects are masked from 'package:stats':
#> 
#>     chisq.test, fisher.test

maize_2024 <- clean_names(maize_2024)
names(maize_2024)
#> [1] "local"              "hibrido"            "bloco"             
#> [4] "prod_kg_ha"         "altura_cm"          "florescimento_dias"
#> [7] "data_plantio"       "obs"

soy <- clean_names(soy)
names(soy)
#> [1] "local"               "cultivar"            "bloco"              
#> [4] "produtividade_sc_ha" "peso_100_sementes_g" "dias_ate_maturacao" 
#> [7] "acamamento"          "data_de_semeadura"

Híbrido became hibrido (hybrid), Prod (kg/ha) became prod_kg_ha and Dias até maturação (days to maturity) became dias_ate_maturacao. Every following lesson uses names in this format.

Two other cleaning functions worth knowing:

# Rows duplicated on the combination of columns that should be unique
get_dupes(maize_2024, local, hibrido, bloco)
#> No duplicate combinations found of: local, hibrido, bloco
#> # A tibble: 0 × 9
#> # ℹ 9 variables: local <chr>, hibrido <chr>, bloco <dbl>, dupe_count <int>,
#> #   prod_kg_ha <dbl>, altura_cm <dbl>, florescimento_dias <dbl>,
#> #   data_plantio <chr>, obs <chr>

# Drop entirely empty rows and columns
remove_empty(maize_2024, which = c("rows", "cols")) |> dim()
#> [1] 240   8

No duplicates: each combination of location, hybrid and block appears once, as expected in a block design.

5.6 Other formats

5.6.1 SPSS, Stata and SAS: haven

Data from collaborators in other fields sometimes arrive in the formats of commercial statistics software. The haven package reads and writes those files and preserves value labels, which are common in those programs:

library(haven)

# Create an example .sav file in a temporary folder
sav_file <- tempfile(fileext = ".sav")

5.7 Saving results

After reading and cleaning, you will want to save the result. The format depends on who will use the file:

Format Function When to use it
CSV write_csv() exchanging data with any software; works well in Git
Semicolon CSV write_csv2() sending to someone who will open it in a locale with a decimal comma
RDS write_rds() keeping an R object exactly as it is (types, factors, lists)
Excel writexl::write_xlsx() handing spreadsheets to collaborators 
tmp_dir <- tempdir()

write_csv(maize_2024, file.path(tmp_dir, "maize_2024.csv"))
write_rds(maize_2024, file.path(tmp_dir, "maize_2024.rds"))
writexl::write_xlsx(maize_2024, file.path(tmp_dir, "maize_2024.xlsx"))

# RDS preserves the tibble and the types; the CSV must be read and interpreted again
identical(read_rds(file.path(tmp_dir, "maize_2024.rds")), maize_2024)
#> [1] TRUE

The lab rule: intermediate files between scripts of the same project go in RDS (fast, keeps types); output files that other people will open go in CSV or Excel.

5.9 Under the hood

5.9.1 How readr guesses types

readr examines the first 1000 rows of each column and picks the most restrictive type that fits every value, in the order logical, integer, double, date, text. If the first “odd” value is on row 5000, the column will be typed wrongly. The guess_max argument enlarges the sample:

read_csv(file, guess_max = Inf)   # examines every row (slower)

The specification used is stored in the object and can be reused:

spec(locais)
#> cols(
#>   .default = col_double(),
#>   local = col_character(),
#>   municipio = col_character(),
#>   uf = col_factor(levels = NULL, ordered = FALSE, include_na = FALSE),
#>   latitude = col_double(),
#>   longitude = col_double(),
#>   altitude_m = col_integer()
#> )

  1. Diagnosis. Why does the read below produce a text Prod (kg/ha) column, and why is that dangerous if you compute the mean right after with as.numeric()?
read_excel(maize_file, sheet = "Londrina", skip = 3)
TipSolution

The codes "-" and "perdida" make the whole column be read as text. If you apply as.numeric() afterwards, they become NA with a generic warning, and the information about why the value is missing is lost. Worse: if there were a number typed with a decimal comma ("9.512,3"), it would also become NA and go unnoticed among the expected codes. Declaring the codes in na = c("-", "perdida") and keeping the Obs column preserves the information and makes any other unexpected text still show up as a problem.

Summary

  • read_csv() for standard CSV; read_delim() with locale(decimal_mark = ",", encoding = "latin1") for the Brazilian convention.
  • Declare types with col_types in production scripts and inspect problems() whenever there is a warning.
  • read_excel() with sheet, skip, range and na handles most field spreadsheets; excel_sheets() lists the sheets.
  • janitor::clean_names() standardises names to snake_case.
  • Save intermediates as RDS and outputs as CSV or Excel. End every import by checking dimensions, types, missing values and categories.
