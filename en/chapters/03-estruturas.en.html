3  Data structures

Lesson goals

By the end of this lesson you will be able to:

  1. Choose the right structure for each kind of information: vector, factor, matrix, list or table.
  2. Select elements by position, by name and by logical condition.
  3. Understand the difference between [, [[ and $, the source of many silent errors.
  4. Use factors for categorical variables and avoid the trap of converting factors to numbers.
  5. Create and inspect data.frames and tibbles, and know why the lab prefers tibble.

3.1 The map of structures

In the previous lesson we saw that every piece of data in R lives inside a vector of a single type. The structures in this lesson are ways of organising those vectors. Two questions decide which one to use:

All elements of the same type Elements of different types
One dimension atomic vector list
Two dimensions matrix data.frame / tibble

A SNP genotype matrix (all numbers 0, 1 or 2) is homogeneous and two-dimensional: a matrix. A trial spreadsheet with cultivar (text), block (integer) and yield (decimal) is heterogeneous and two-dimensional: a data.frame. The output of a model, with coefficients, residuals and the formula used, is heterogeneous and free-form: a list.

3.2 Vectors: selecting elements

We will use the yield of six soybean cultivars in bags per hectare:

yield <- c(62.4, 58.1, 70.3, 66.0, 65.8, 54.9)
names(yield) <- c("SJ-01", "SJ-02", "SJ-03", "SJ-04", "SJ-05", "SJ-06")
yield
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  62.4  58.1  70.3  66.0  65.8  54.9

The [ operator selects elements. There are four ways of saying which ones:

# 1. By position (R starts counting at 1, not 0)
yield[3]
#> SJ-03 
#>  70.3
yield[c(1, 3, 5)]
#> SJ-01 SJ-03 SJ-05 
#>  62.4  70.3  65.8
yield[2:4]
#> SJ-02 SJ-03 SJ-04 
#>  58.1  70.3  66.0

# 2. By exclusion: negative indices drop elements
yield[-1]
#> SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  58.1  70.3  66.0  65.8  54.9
yield[-c(1, 2)]
#> SJ-03 SJ-04 SJ-05 SJ-06 
#>  70.3  66.0  65.8  54.9

# 3. By name
yield["SJ-04"]
#> SJ-04 
#>    66
yield[c("SJ-01", "SJ-06")]
#> SJ-01 SJ-06 
#>  62.4  54.9

# 4. By logical condition: the logical vector acts as a filter
yield[yield > 65]
#> SJ-03 SJ-04 SJ-05 
#>  70.3  66.0  65.8

The fourth form is the most powerful and the one you will use most. It helps to see what happens in two steps:

yield > 65          # first, a logical vector of the same length
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#> FALSE FALSE  TRUE  TRUE  TRUE FALSE
yield[yield > 65]   # then only the TRUE positions are kept
#> SJ-03 SJ-04 SJ-05 
#>  70.3  66.0  65.8

Conditions can be combined with & (and), | (or) and ! (not):

yield[yield > 60 & yield < 68]
#> SJ-01 SJ-04 SJ-05 
#>  62.4  66.0  65.8
yield[!(names(yield) %in% c("SJ-01", "SJ-02"))]
#> SJ-03 SJ-04 SJ-05 SJ-06 
#>  70.3  66.0  65.8  54.9

The %in% operator asks “is this element in this set?” and is indispensable for filtering lists of cultivars or markers.

To know where the elements meeting a condition are, use which():

which(yield > 65)
#> SJ-03 SJ-04 SJ-05 
#>     3     4     5
which.max(yield)
#> SJ-03 
#>     3

3.2.1 Going out of bounds

yield[10]
#> <NA> 
#>   NA

Asking for a position that does not exist does not raise an error: it returns NA. This silent behaviour is a good reason to check length() before indexing by position.

3.2.2 Modifying elements

The same syntax replaces values:

yield["SJ-02"] <- 59.0
yield[yield < 56] <- NA   # flag a suspicious value as missing
yield
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  62.4  59.0  70.3  66.0  65.8    NA

3.3 Factors: categorical variables

Block, location, cultivar and resistance class are categories, not free text. R has a dedicated structure for them, the factor:

block <- factor(c(1, 2, 3, 1, 2, 3, 1, 2, 3))
block
#> [1] 1 2 3 1 2 3 1 2 3
#> Levels: 1 2 3
levels(block)
#> [1] "1" "2" "3"
nlevels(block)
#> [1] 3
table(block)
#> block
#> 1 2 3 
#> 3 3 3

A factor stores two things: the levels (the possible categories) and, for each observation, which level it belongs to. That brings three advantages:

  1. Statistical models treat factors as categories. If block were numeric, lm() would estimate a slope for “block”, which makes no sense. As a factor, it estimates one effect per block.
  2. The levels set the order in tables and plots.
  3. Levels with no observations still exist, which is useful to show that a category ended up empty.

3.3.1 Level order and ordered factors

By default, levels are sorted alphabetically. When the order is meaningful, specify it:

reaction <- c("susceptible", "resistant", "moderate", "resistant", "susceptible")

factor(reaction)   # alphabetical: moderate, resistant, susceptible
#> [1] susceptible resistant   moderate    resistant   susceptible
#> Levels: moderate resistant susceptible

reaction_f <- factor(
  reaction,
  levels = c("resistant", "moderate", "susceptible"),
  ordered = TRUE
)
reaction_f
#> [1] susceptible resistant   moderate    resistant   susceptible
#> Levels: resistant < moderate < susceptible
reaction_f < "susceptible"   # comparisons only make sense for ordered factors
#> [1] FALSE  TRUE  TRUE  TRUE FALSE

Values that are not among the levels become NA, with no error. Watch out for typos:

factor(c("resistant", "Resistant"), levels = c("resistant", "moderate", "susceptible"))
#> [1] resistant <NA>     
#> Levels: resistant moderate susceptible

3.3.2 The trap: turning a factor into a number

Internally, a factor is a vector of integers with a label for each integer. This leads to one of the most treacherous errors in R:

dose_kg_ha <- factor(c("60", "90", "120", "60", "120"))
as.numeric(dose_kg_ha)     # wrong! these are the internal level codes
#> [1] 2 3 1 2 1

The levels are in alphabetical order ("120", "60", "90"), so R returned 1, 2 and 3 instead of the doses. The correct way goes through text:

as.numeric(as.character(dose_kg_ha))
#> [1]  60  90 120  60 120

In lesson 8 we will meet the forcats package, which makes working with factors (reordering, renaming, lumping levels) much clearer.

3.4 Matrices

A matrix is an atomic vector arranged in rows and columns. The classic example in genetics is the marker matrix: each row an individual, each column a SNP, and each cell the number of copies of the reference allele (0, 1 or 2).

markers <- matrix(
  c(0, 1, 2, 1, 0,
    1, 1, 2, 0, 0,
    2, 1, 1, 0, 1,
    0, 2, 2, 1, 0),
  nrow = 4,
  byrow = TRUE,
  dimnames = list(
    c("HB01", "HB02", "HB03", "HB04"),
    c("snp1", "snp2", "snp3", "snp4", "snp5")
  )
)
markers
#>      snp1 snp2 snp3 snp4 snp5
#> HB01    0    1    2    1    0
#> HB02    1    1    2    0    0
#> HB03    2    1    1    0    1
#> HB04    0    2    2    1    0
dim(markers)
#> [1] 4 5

The byrow = TRUE argument fills the matrix row by row, the order in which we typed the values. Without it, R would fill it column by column.

Indexing uses [row, column]; leaving a position empty means “all”:

markers["HB02", ]          # every SNP for HB02
#> snp1 snp2 snp3 snp4 snp5 
#>    1    1    2    0    0
markers[, "snp3"]          # snp3 for every hybrid
#> HB01 HB02 HB03 HB04 
#>    2    2    1    2
markers[1:2, c("snp1", "snp5")]
#>      snp1 snp5
#> HB01    0    0
#> HB02    1    0

Arithmetic is still vectorised, and there are dedicated functions for rows and columns:

# Reference allele frequency at each SNP
colMeans(markers) / 2
#>  snp1  snp2  snp3  snp4  snp5 
#> 0.375 0.625 0.875 0.250 0.125

# Number of heterozygous loci (value 1) in each hybrid
rowSums(markers == 1)
#> HB01 HB02 HB03 HB04 
#>    2    2    3    1

3.4.1 The silent drop

When you select a single column, the matrix “collapses” into a vector:

markers[, "snp3"]
#> HB01 HB02 HB03 HB04 
#>    2    2    1    2
markers[, "snp3", drop = FALSE]
#>      snp3
#> HB01    2
#> HB02    2
#> HB03    1
#> HB04    2

When you write a function that must always receive a matrix, use drop = FALSE. This behaviour is a common source of bugs in genetics code, when a quality filter happens to leave a single marker.

We will return to matrices in depth in lesson 27 (matrix algebra) and in Module 5 (relationship matrices). To go beyond two dimensions there are arrays (array()), useful, for example, to store one marker matrix per chromosome.

3.5 Lists

A list is a vector in which each element can be anything: a number, a string, a vector, a matrix, another list. It is R’s most flexible structure:

trial <- list(
  name = "Soybean cultivar trial",
  locations = c("Viçosa", "Rio Verde"),
  n_blocks = 4L,
  markers = markers
)
str(trial)
#> List of 4
#>  $ name     : chr "Soybean cultivar trial"
#>  $ locations: chr [1:2] "Viçosa" "Rio Verde"
#>  $ n_blocks : int 4
#>  $ markers  : num [1:4, 1:5] 0 1 2 0 1 1 1 2 2 2 ...
#>   ..- attr(*, "dimnames")=List of 2
#>   .. ..$ : chr [1:4] "HB01" "HB02" "HB03" "HB04"
#>   .. ..$ : chr [1:5] "snp1" "snp2" "snp3" "snp4" ...

str() (for structure) is the best way to look at a list: it shows the name, the type and the start of the content of each element.

3.5.1 [, [[ and $

This is the most important distinction in the lesson. Think of the list as a sample box with labelled compartments:

  • [ returns a smaller box, still a list, containing the chosen compartments.
  • [[ opens the compartment and returns its contents.
  • $ is a shortcut for [[ with the name written directly.
trial["locations"]        # a list with one element
#> $locations
#> [1] "Viçosa"    "Rio Verde"
class(trial["locations"])
#> [1] "list"

trial[["locations"]]      # the character vector itself
#> [1] "Viçosa"    "Rio Verde"
class(trial[["locations"]])
#> [1] "character"

trial$locations           # the same as trial[["locations"]]
#> [1] "Viçosa"    "Rio Verde"

The difference shows up when you try to use the result:

length(trial["locations"])     # 1: the "box" has one compartment
#> [1] 1
length(trial[["locations"]])   # 2: the vector has two locations
#> [1] 2
trial["n_blocks"] * 2          # error: you cannot multiply a list
#> Error in `trial["n_blocks"] * 2`:
#> ! non-numeric argument to binary operator
trial[["n_blocks"]] * 2
#> [1] 8

You can also chain selections to reach something inside an element:

trial$locations[2]
#> [1] "Rio Verde"
trial$markers["HB03", "snp1"]
#> [1] 2

3.5.2 Why lists matter

You will rarely build complex lists by hand, but you will receive them all the time. Almost every modelling function returns a list:

model <- lm(dist ~ speed, data = cars)
typeof(model)
#> [1] "list"
names(model)
#>  [1] "coefficients"  "residuals"     "effects"       "rank"         
#>  [5] "fitted.values" "assign"        "qr"            "df.residual"  
#>  [9] "xlevels"       "call"          "terms"         "model"
model$coefficients
#> (Intercept)       speed 
#>  -17.579095    3.932409

In Module 2, the purrr package will make lists a central tool: we will fit one model per environment and keep them all in a list.

3.6 Tables: data.frame

A data.frame is the structure of spreadsheets: each column is a vector (with its own type) and all columns have the same length.

soy <- data.frame(
  cultivar = c("SJ-01", "SJ-02", "SJ-03", "SJ-04"),
  block = factor(c(1, 1, 2, 2)),
  yield_bags_ha = c(62.4, 58.1, 70.3, 66.0),
  lodging = c(FALSE, FALSE, TRUE, FALSE)
)
soy
#>   cultivar block yield_bags_ha lodging
#> 1    SJ-01     1          62.4   FALSE
#> 2    SJ-02     1          58.1   FALSE
#> 3    SJ-03     2          70.3    TRUE
#> 4    SJ-04     2          66.0   FALSE

Inspection functions you will use on every new dataset:

str(soy)
#> 'data.frame':    4 obs. of  4 variables:
#>  $ cultivar     : chr  "SJ-01" "SJ-02" "SJ-03" "SJ-04"
#>  $ block        : Factor w/ 2 levels "1","2": 1 1 2 2
#>  $ yield_bags_ha: num  62.4 58.1 70.3 66
#>  $ lodging      : logi  FALSE FALSE TRUE FALSE
nrow(soy)
#> [1] 4
ncol(soy)
#> [1] 4
names(soy)
#> [1] "cultivar"      "block"         "yield_bags_ha" "lodging"
summary(soy)
#>       cultivar block yield_bags_ha    lodging       
#>  Length   :4   1:2   Min.   :58.10   Mode :logical  
#>  N.unique :4   2:2   1st Qu.:61.33   FALSE:3        
#>  N.blank  :0         Median :64.20   TRUE :1        
#>  Min.nchar:5         Mean   :64.20                  
#>  Max.nchar:5         3rd Qu.:67.08                  
#>                      Max.   :70.30

Indexing combines what we saw for matrices and lists:

soy$yield_bags_ha                     # one column, as a vector
#> [1] 62.4 58.1 70.3 66.0
soy[["cultivar"]]                     # likewise
#> [1] "SJ-01" "SJ-02" "SJ-03" "SJ-04"
soy[soy$yield_bags_ha > 60, ]         # rows meeting a condition
#>   cultivar block yield_bags_ha lodging
#> 1    SJ-01     1          62.4   FALSE
#> 3    SJ-03     2          70.3    TRUE
#> 4    SJ-04     2          66.0   FALSE
soy[, c("cultivar", "lodging")]       # some columns
#>   cultivar lodging
#> 1    SJ-01   FALSE
#> 2    SJ-02   FALSE
#> 3    SJ-03    TRUE
#> 4    SJ-04   FALSE
soy$yield_t_ha <- soy$yield_bags_ha * 60 / 1000  # new column
soy
#>   cultivar block yield_bags_ha lodging yield_t_ha
#> 1    SJ-01     1          62.4   FALSE      3.744
#> 2    SJ-02     1          58.1   FALSE      3.486
#> 3    SJ-03     2          70.3    TRUE      4.218
#> 4    SJ-04     2          66.0   FALSE      3.960

From lesson 6 onwards we will do these operations with dplyr, which is more readable. But it is important to know the base form: you will find it in older code, inside packages and in answers online.

3.6.1 The data.frame gotchas

data.frame has behaviours inherited from decades ago that surprise newcomers:

soy[, "cultivar"]       # selected one column... and returned a vector, not a table
#> [1] "SJ-01" "SJ-02" "SJ-03" "SJ-04"
soy$lodg                # completed "lodg" to "lodging" without warning!
#> [1] FALSE FALSE  TRUE FALSE

The second case, called partial matching, is dangerous: if you mistype a column name, R may return another column without saying anything.

3.7 Modern tables: tibble

NotePackage intent: tibble

Problem it solves. The surprising behaviours of data.frame (silent conversion to a vector, partial matching, printing thousands of rows in the console) let bugs slip through unnoticed.

Philosophy. A tibble is a more cautious data.frame: it does fewer things on its own and warns you earlier when something looks wrong. It does not change types, does not complete names, does not create row names and prints only what fits on screen, showing the type of each column.

Why this one and not the alternatives. A tibble is still a data.frame: any function that accepts a data.frame accepts a tibble. We gain safety without losing compatibility. It is also the format returned by every tidyverse package (readr, dplyr, tidyr), so adopting it now avoids converting back and forth. The data.table alternative is excellent for very large data and will be covered in lesson 18, but it has its own syntax that we prefer to introduce later.

library(tibble)

soy_tb <- tibble(
  cultivar = c("SJ-01", "SJ-02", "SJ-03", "SJ-04"),
  block = factor(c(1, 1, 2, 2)),
  yield_bags_ha = c(62.4, 58.1, 70.3, 66.0),
  yield_t_ha = yield_bags_ha * 60 / 1000   # uses a column just created
)
soy_tb
#> # A tibble: 4 × 4
#>   cultivar block yield_bags_ha yield_t_ha
#>   <chr>    <fct>         <dbl>      <dbl>
#> 1 SJ-01    1              62.4       3.74
#> 2 SJ-02    1              58.1       3.49
#> 3 SJ-03    2              70.3       4.22
#> 4 SJ-04    2              66         3.96

Look at the printout: the dimensions (4 × 4) and, under each name, the column type (<chr>, <fct>, <dbl>). Compare the gotchas:

soy_tb[, "cultivar"]    # still a tibble
#> # A tibble: 4 × 1
#>   cultivar
#>   <chr>   
#> 1 SJ-01   
#> 2 SJ-02   
#> 3 SJ-03   
#> 4 SJ-04
soy_tb$yield            # NULL and a warning, instead of guessing the column
#> Warning: Unknown or uninitialised column: `yield`.
#> NULL

To type small tables in code, tribble() lets you write row by row, which is much more readable:

locations <- tribble(
  ~location,     ~state, ~altitude_m,
  "Viçosa",      "MG",   650,
  "Rio Verde",   "GO",   750,
  "Londrina",    "PR",   585
)
locations
#> # A tibble: 3 × 3
#>   location  state altitude_m
#>   <chr>     <chr>      <dbl>
#> 1 Viçosa    MG           650
#> 2 Rio Verde GO           750
#> 3 Londrina  PR           585

And as_tibble() converts an existing data.frame:

as_tibble(soy)
#> # A tibble: 4 × 5
#>   cultivar block yield_bags_ha lodging yield_t_ha
#>   <chr>    <fct>         <dbl> <lgl>        <dbl>
#> 1 SJ-01    1              62.4 FALSE         3.74
#> 2 SJ-02    1              58.1 FALSE         3.49
#> 3 SJ-03    2              70.3 TRUE          4.22
#> 4 SJ-04    2              66   FALSE         3.96

3.8 Under the hood

3.8.1 A data.frame is a list

typeof(soy)
#> [1] "list"
is.list(soy)
#> [1] TRUE
length(soy)     # the number of columns!
#> [1] 5

A data.frame is a list of vectors of equal length, with the attributes names, row.names and class. That is why soy[["cultivar"]] and soy$cultivar work: they are list operations.

attributes(soy)
#> $names
#> [1] "cultivar"      "block"         "yield_bags_ha" "lodging"      
#> [5] "yield_t_ha"   
#> 
#> $row.names
#> [1] 1 2 3 4
#> 
#> $class
#> [1] "data.frame"

3.8.2 A factor is an integer with labels

typeof(block)
#> [1] "integer"
attributes(block)
#> $levels
#> [1] "1" "2" "3"
#> 
#> $class
#> [1] "factor"
unclass(block)
#> [1] 1 2 3 1 2 3 1 2 3
#> attr(,"levels")
#> [1] "1" "2" "3"

3.8.3 A matrix is a vector with dimensions

v <- 1:6
dim(v) <- c(2, 3)
v
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6

Assigning the dim attribute to a vector turns it into a matrix. This pattern (complex structures as simple vectors plus attributes) explains much of R’s consistency.

3.9 Exercises

  1. Selecting from vectors. With the vector height_cm <- c(HB01 = 212, HB02 = 230, HB03 = 198, HB04 = 241, HB05 = 225), select: (a) the height of HB03; (b) all but HB01; (c) the hybrids taller than 220 cm; (d) the name of the tallest hybrid.
TipSolution 
height_cm <- c(HB01 = 212, HB02 = 230, HB03 = 198, HB04 = 241, HB05 = 225)
height_cm["HB03"]
#> HB03 
#>  198
height_cm[-1]
#> HB02 HB03 HB04 HB05 
#>  230  198  241  225
height_cm[height_cm > 220]
#> HB02 HB04 HB05 
#>  230  241  225
names(which.max(height_cm))
#> [1] "HB04"
  1. Factors. Create an ordered factor from the disease severity scores c("low", "high", "medium", "low", "high", "high"), with levels in increasing order of severity. Count how many plots fall in each level and how many have severity above “low”.
TipSolution 
severity <- factor(
  c("low", "high", "medium", "low", "high", "high"),
  levels = c("low", "medium", "high"),
  ordered = TRUE
)
table(severity)
#> severity
#>    low medium   high 
#>      2      1      3
sum(severity > "low")
#> [1] 4
  1. Marker matrix. Using this lesson’s markers matrix, compute the reference allele frequency for each SNP and identify the SNPs with frequency between 0.2 and 0.8. Select the submatrix with only those SNPs, making sure the result is a matrix.
TipSolution 
freq <- colMeans(markers) / 2
freq
#>  snp1  snp2  snp3  snp4  snp5 
#> 0.375 0.625 0.875 0.250 0.125
selected <- names(freq)[freq >= 0.2 & freq <= 0.8]
markers[, selected, drop = FALSE]
#>      snp1 snp2 snp4
#> HB01    0    1    1
#> HB02    1    1    0
#> HB03    2    1    0
#> HB04    0    2    1
  1. Lists. From the trial list, extract: (a) the number of blocks multiplied by the number of locations; (b) the genotype of HB04 at snp2. Explain why trial["n_blocks"] * length(trial["locations"]) does not give the expected result.
TipSolution 
trial$n_blocks * length(trial$locations)
#> [1] 8
trial$markers["HB04", "snp2"]
#> [1] 2

trial["n_blocks"] is a list, and lists do not support arithmetic (error). And length(trial["locations"]) is 1, the number of elements in the sublist, not 2, the number of locations.

  1. From data.frame to tibble. Create a tibble with 3 hybrids (HB01 to HB03), their days to flowering (61, 64, 59) and a column early that is TRUE when flowering is under 62 days, built from the flowering column inside tibble() itself.
TipSolution 
tibble(
  hybrid = c("HB01", "HB02", "HB03"),
  days_to_flowering = c(61, 64, 59),
  early = days_to_flowering < 62
)
#> # A tibble: 3 × 3
#>   hybrid days_to_flowering early
#>   <chr>              <dbl> <lgl>
#> 1 HB01                  61 TRUE 
#> 2 HB02                  64 FALSE
#> 3 HB03                  59 TRUE

Summary

  • Vectors and matrices are homogeneous; lists and data.frames accept different types.
  • Select by position, exclusion, name or logical condition; %in% and which() complete the kit.
  • Factors represent categories; set the level order and never convert a factor straight to a number.
  • In lists, [ returns a sublist and [[/$ return the contents.
  • Use drop = FALSE when the result must remain a matrix or table.
  • Prefer tibble to data.frame: same compatibility, fewer surprises.
