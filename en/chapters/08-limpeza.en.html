8.1 stringr: working with text

NotePackage intent: stringr

Problem it solves. Base R’s text functions (grepl(), sub(), gsub(), regmatches(), substr(), toupper()) have unhelpful names, different argument orders and inconsistent behaviour with NA.

Philosophy. In stringr, every function starts with str_ and takes the text as its first argument and the pattern as its second. That lets RStudio’s autocomplete work for you (type str_ and see the list) and fits every function into the pipe and mutate(). Under the hood it uses the stringi package, which handles accents and characters from any language correctly.

Why this one and not the alternatives. Base R does it all, but remembering whether it is grepl(pattern, x) or grepl(x, pattern) takes time and causes bugs. stringi is more complete but much larger; stringr gathers the everyday operations into about 50 consistent functions.

8.1.2 Cleaning step by step

Each problem has a function:

examples <- c(" SJ-01 ", "sj-01", "SJ 01", "SJ-01")

str_squish(examples)       # removes spaces at the ends and repeated spaces inside
#> [1] "SJ-01" "sj-01" "SJ 01" "SJ-01"
str_to_upper(examples)     # everything upper case
#> [1] " SJ-01 " "SJ-01"   "SJ 01"   "SJ-01"
str_replace(examples, " ", "-")   # replaces the first space with a hyphen
#> [1] "-SJ-01 " "sj-01"   "SJ-01"   "SJ-01"

Chained, in the right order:

examples |>
  str_squish() |>
  str_to_upper() |>
  str_replace(" ", "-")
#> [1] "SJ-01" "SJ-01" "SJ-01" "SJ-01"

Order matters: if we replaced spaces with hyphens before str_squish(), " SJ-01 " would become "-SJ-01-". Applied to the table:

8.2 Essential regular expressions

A regular expression (regex) is a language for describing text patterns. You do not need to master it; a dozen symbols solve most trial-data cases:

Symbol Meaning Example
\\d a digit "\\d\\d" matches "07"
\\s a space (or tab)
. any character
+ one or more repetitions "\\d+" matches "7" and "120"
* zero or more repetitions
{n} exactly n repetitions "\\d{2}"
^ and $ start and end of the text "^SJ" only matches at the start
[abc] one of the listed characters "[ -]" matches a space or a hyphen
( ) groups and captures
\| or "lost\|missing"

In R the backslash has to be written twice inside strings, hence \\d.

# Extract the cultivar number
str_extract(codes, "\\d+")
#> [1] "01" "12" "03" "7"

# Validate the format: two letters, hyphen, exactly two digits
str_detect(codes, "^[A-Z]{2}-\\d{2}$")
#> [1]  TRUE  TRUE  TRUE FALSE

# Fix: zero-pad a single-digit number at the end
str_replace(codes, "-(\\d)$", "-0\\1")
#> [1] "SJ-01" "SJ-12" "HB-03" "SJ-07"

In the last example, (\\d) captures the digit and \\1 puts it back in the replacement. Validation is good practice to leave in the cleaning script: if a code outside the pattern shows up in a future season, you find out immediately.

stopifnot(all(str_detect(soy$cultivar, "^SJ-\\d{2}$")))

stopifnot() does nothing if the condition is true and stops the script with an error if it is false. It is the simplest way to test your data inside the script itself.

8.3 forcats: controlling factors

NotePackage intent: forcats

Problem it solves. Factors are essential in models and plots, but reordering, renaming or merging levels in base R means manipulating levels() directly, which is easy to get wrong (remember the trap from lesson 3).

Philosophy. Every forcats function starts with fct_ and does one clear operation on the levels, never accidentally touching the observations’ values: reorder by another variable (fct_reorder), by frequency (fct_infreq), by hand (fct_relevel); rename (fct_recode); lump rare levels (fct_lump_n).

Why this one and not the alternatives. The same operations are possible with factor(x, levels = ...) and levels(x) <- ..., but with a real risk of swapping the observations’ labels. forcats is part of the tidyverse and was built precisely to make these operations safe.

soy <- soy |>
  mutate(
    local = factor(local),
    cultivar = factor(cultivar),
    bloco = factor(bloco)
  )

levels(soy$local)
#> [1] "Rio Verde" "Viçosa"

8.3.1 Reordering

By default levels are in alphabetical order. In tables and plots it is almost always more useful to order by a statistic. fct_reorder() orders a factor’s levels by the values of another variable:

soy <- soy |>
  mutate(cultivar = fct_reorder(cultivar, produtividade_sc_ha, .fun = median, .na_rm = TRUE))

levels(soy$cultivar)   # from the lowest to the highest median yield
#>  [1] "SJ-05" "SJ-04" "SJ-01" "SJ-12" "SJ-06" "SJ-03" "SJ-11" "SJ-14" "SJ-02"
#> [10] "SJ-07" "SJ-09" "SJ-15" "SJ-13" "SJ-08" "SJ-10"

In lesson 19 this will be the trick for ordered bar charts. Other ways to reorder:

fct_relevel(soy$local, "Viçosa") |> levels()   # moves one level to the front
#> [1] "Viçosa"    "Rio Verde"
fct_rev(soy$local) |> levels()                 # reverses the order
#> [1] "Viçosa"    "Rio Verde"
fct_infreq(c("b", "a", "b", "c", "b", "a")) |> levels()   # by frequency
#> [1] "b" "a" "c"

fct_relevel() matters in models: the first level is the reference for contrasts in lm(). If the trial’s check cultivar is SJ-15, putting it first makes the coefficients measure each cultivar’s difference from the check.

8.4 lubridate: dates

NotePackage intent: lubridate

Problem it solves. Dates arrive in varied formats (22/10/2023, 2023-10-22, 22-Oct-2023) and base R requires you to spell out the format with codes such as "%d/%m/%Y". Computing intervals, adding days or extracting the month also takes a different function for each case.

Philosophy. In lubridate, the function name describes the order of the date components: dmy() for day-month-year, ymd() for year-month-day, mdy() for the US format. It recognises separators automatically and offers obviously named functions to extract parts (year(), month(), yday()) and to add periods (days(), months()).

Why this one and not the alternatives. as.Date(x, format = "%d/%m/%Y") works and is what lubridate does underneath, but it fails on mixed formats and requires memorising the codes. For field data, where the same spreadsheet has dates typed in different ways, lubridate saves a lot of work.

dmy("22/10/2023")
#> [1] "2023-10-22"
dmy("22-10-2023")
#> [1] "2023-10-22"
dmy("22 October 2023")
#> [1] "2023-10-22"
ymd("2023-10-22")
#> [1] "2023-10-22"

A date in R is a number of days since 1 January 1970, with class Date:

date <- dmy("22/10/2023")
class(date)
#> [1] "Date"
as.numeric(date)
#> [1] 19652

8.4.1 Mixed formats

The sowing column has the formats dd/mm/yyyy and yyyy-mm-dd. dmy() alone would fail on the latter. parse_date_time() takes a list of possible formats and tries each one:

soy |> count(str_detect(data_de_semeadura, "/"))
#> # A tibble: 2 × 2
#>   `str_detect(data_de_semeadura, "/")`     n
#>   <lgl>                                <int>
#> 1 FALSE                                   23
#> 2 TRUE                                    97

soy <- soy |>
  mutate(sowing_date = as_date(parse_date_time(data_de_semeadura, orders = c("dmy", "ymd")))) |>
  select(-data_de_semeadura)

soy |> count(local, sowing_date)
#> # A tibble: 6 × 3
#>   local     sowing_date     n
#>   <fct>     <date>      <int>
#> 1 Rio Verde 2024-10-27     20
#> 2 Rio Verde 2024-10-28     20
#> 3 Rio Verde 2024-10-29     20
#> 4 Viçosa    2024-10-15     22
#> 5 Viçosa    2024-10-16     19
#> 6 Viçosa    2024-10-17     19
sum(is.na(soy$sowing_date))
#> [1] 0

No dates lost, and the sowing dates at each location are close together, as expected.

WarningAmbiguous formats

Is "03/04/2024" 3 April (Brazilian and European convention) or 4 March (US convention)? No function can guess. When there are dates like this, confirm the convention with whoever typed the data and use a single format in orders. parse_date_time() with several formats is safe here because dmy and ymd can never be confused (the four-digit year sits in different positions).

8.6 The clean soybean trial

Putting everything into a single pipeline, which will be the template for the cleaning script in lesson 9:

soy_clean <- read_delim(
  here("data", "raw", "soja_ensaio_2025.csv"),

8.7 Under the hood

8.7.1 Text encoding

Every string in R has an encoding. After reading with locale(encoding = "latin1"), readr converted everything to UTF-8:

Encoding("Viçosa")
#> [1] "UTF-8"
utf8ToInt("ç")          # the character's Unicode code point
#> [1] 231
charToRaw("Viçosa")     # the bytes: "ç" takes two in UTF-8
#> [1] 56 69 c3 a7 6f 73 61

If you ever need to compare strings with and without accents (for example "Vicosa" and "Viçosa"), strip the accents explicitly:

stringi::stri_trans_general("Viçosa, São Paulo", "Latin-ASCII")
#> [1] "Vicosa, Sao Paulo"

8.7.2 Dates and time zones

parse_date_time() returns a POSIXct (date and time), which is why we used as_date() to keep only the date. Date-times carry a time zone, which can shift the day in a careless conversion. For daily field data, always work with Date.

parse_date_time("2024-10-15", "ymd")
#> [1] "2024-10-15 UTC"
as_date(parse_date_time("2024-10-15", "ymd"))
#> [1] "2024-10-15"

TipSolution 
locations <- c("Viçosa", "VIÇOSA", " viçosa", "Vicosa", "Rio Verde", "rio  verde")

locations |>
  str_squish() |>
  str_to_title() |>
  str_replace("^Vicosa$", "Viçosa")
#> [1] "Viçosa"    "Viçosa"    "Viçosa"    "Viçosa"    "Rio Verde" "Rio Verde"

str_to_title() capitalises the first letter of each word. The spelling without the cedilla needs an explicit fix, because no general rule knows that “Vicosa” should have one.

  1. Regex. From the vector c("HB01-B1", "HB12-B3", "HB7-B2", "hb05-b1"), extract the hybrid number (as a number) and the block number, and identify which codes do not follow the pattern HB + two digits + -B + one digit.
TipSolution 
plots <- c("HB01-B1", "HB12-B3", "HB7-B2", "hb05-b1")

str_extract(plots, "(?i)hb(\\d+)", group = 1) |> as.integer()
#> [1]  1 12  7  5
str_extract(plots, "(?i)b(\\d)$", group = 1) |> as.integer()
#> [1] 1 3 2 1
plots[!str_detect(plots, "^HB\\d{2}-B\\d$")]
#> [1] "HB7-B2"  "hb05-b1"

(?i) at the start of the pattern ignores case; group = 1 returns only what the parentheses captured.

  1. The check as reference. In the clean soybean trial, make SJ-15 the first level of cultivar and check with levels(). Why would this change the coefficients of lm(produtividade_sc_ha ~ cultivar)?
TipSolution 
soy_clean <- soy_clean |> mutate(cultivar = fct_relevel(cultivar, "SJ-15"))
levels(soy_clean$cultivar)[1:3]
#> [1] "SJ-15" "SJ-01" "SJ-02"

In lm(), the first level becomes the reference: the intercept becomes the mean of SJ-15 and each coefficient the difference between a cultivar and SJ-15. Fitted values and the F test do not change; only the interpretation of the coefficients does.

  1. Maize dates. In the 2023/24 maize trial (lesson 5), the data_plantio (planting date) column is text in dd/mm/yyyy format. Convert it to a date and compute each plot’s likely flowering date by adding florescimento_dias. In which month did most plots flower?
TipSolution 
maize_file <- here("data", "raw", "milho_met_2024.xlsx")

readxl::excel_sheets(maize_file) |>
  set_names() |>
  map(\(sheet) readxl::read_excel(maize_file, sheet = sheet, skip = 3, na = c("", "-", "perdida"))) |>
  list_rbind(names_to = "local") |>
  clean_names() |>
  mutate(
    data_plantio = dmy(data_plantio),
    flowering_date = data_plantio + days(florescimento_dias)
  ) |>
  count(month = month(flowering_date))
#> # A tibble: 2 × 2
#>   month     n
#>   <dbl> <int>
#> 1     1     3
#> 2    12   237

Summary

  • stringr: str_squish(), str_to_upper(), str_replace(), str_detect() and str_extract() handle most text cleaning; the order of operations matters.
  • Regular expressions describe patterns; use them to validate codes with stopifnot().
  • forcats: fct_reorder() orders by a statistic, fct_relevel() sets the model reference, fct_recode() renames, fct_drop() removes empty levels.
  • lubridate: dmy()/ymd() for known formats, parse_date_time() for mixed formats, days() and month() to compute and extract.
  • Handle missing values on purpose with na_if(), coalesce() and if_any(), and document how many there are.
