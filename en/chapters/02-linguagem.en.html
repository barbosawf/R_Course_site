2  R as a language

Lesson goals

By the end of this lesson you will be able to:

  1. Use R as a calculator and understand why 0.1 + 0.2 == 0.3 is false.
  2. Create objects, name them following the lab style and understand what assignment really does.
  3. Recognise the four main atomic types (logical, integer, double, character) and predict the result of a coercion.
  4. Tell NA, NULL, NaN and Inf apart, and handle missing values in calculations.
  5. Call functions with positional and named arguments, and write a simple function.
  6. Find help and read an error message systematically.

We do not use any package in this lesson: everything here is part of base R. The data come from a small soybean trial typed directly into the code, so you can follow every value.

NoteBags per hectare

Brazilian growers and breeders often report soybean yield in bags per hectare (sacas/ha), where one bag holds 60 kg of grain. We keep that unit in the examples because it is what lab data look like, and convert it to t/ha along the way.

2.1 The console as a calculator

The most direct way to get to know a language is to talk to it. Type in the console:

62.4 + 58.1     # addition
#> [1] 120.5
70.3 - 65.8     # subtraction
#> [1] 4.5
3 * 60          # multiplication: 3 bags of 60 kg
#> [1] 180
180 / 1000      # division: kg to tonnes
#> [1] 0.18
2^10            # power
#> [1] 1024

Two lesser-known operators show up often when arranging plots into blocks and rows:

17 %/% 5   # integer division: how many full blocks of 5 plots fit in 17?
#> [1] 3
17 %% 5    # remainder: how many plots are left over?
#> [1] 2

The order of operations follows mathematics: powers, then multiplication and division, then addition and subtraction. When in doubt, use parentheses; they also make the code easier to read.

2 + 3 * 4
#> [1] 14
(2 + 3) * 4
#> [1] 20
-2^2      # careful: the power comes before the minus sign
#> [1] -4
(-2)^2
#> [1] 4

Very large or very small numbers are shown in scientific notation, and you can type them that way:

1.5e6     # 1.5 million plants per hectare? Check the density!
#> [1] 1500000
2.3e-4    # a rare allele frequency
#> [1] 0.00023
WarningDecimal point, not comma

In R the decimal separator is always the point. 62,4 is not a number: the comma separates function arguments. In lesson 5 we will see how to read spreadsheets that use a decimal comma, as Brazilian ones do, without editing them.

2.1.1 Why 0.1 + 0.2 == 0.3 is false

0.1 + 0.2 == 0.3
#> [1] FALSE

This is not an R bug. Computers store decimal numbers in base 2, and fractions such as 0.1 have no exact binary representation, just as 1/3 has no exact decimal one. The stored value is very close to 0.1, but not identical:

print(0.1 + 0.2, digits = 17)
#> [1] 0.30000000000000004
print(0.3, digits = 17)
#> [1] 0.29999999999999999

The difference is tiny, but enough for == to answer FALSE. To compare decimal numbers, use a tolerance:

all.equal(0.1 + 0.2, 0.3)
#> [1] TRUE
isTRUE(all.equal(0.1 + 0.2, 0.3))   # the safe form to use inside an if
#> [1] TRUE

This matters in practice: when checking that the allele frequencies at a locus add up to 1, or that a relationship matrix is symmetric, compare with a tolerance, never with ==.

2.2 Objects and assignment

Results that vanish in the console are not much use. To keep them, we create objects with the assignment operator <-:

bag_weight_kg <- 60
yield_bags_ha <- 62.4

yield_bags_ha * bag_weight_kg / 1000   # t/ha
#> [1] 3.744

Read <- as “gets”: bag_weight_kg gets 60. In RStudio, the shortcut Alt + - inserts the operator with the right spacing.

Tip<- or =?

Both work for top-level assignment, but the lab style (and that of most of the community) is to use <- to assign and keep = for function arguments, as in round(x, digits = 2). Code is easier to read when each symbol has a single role.

2.2.1 Rules and style for names

R accepts names made of letters, numbers, . and _, as long as they do not start with a number or _. It is case-sensitive: Yield and yield are different objects.

The lab style:

  • snake_case: lower-case words separated by _ (yield_bags_ha, n_plots).
  • Descriptive names and, where relevant, with the unit (height_cm, days_to_maturity). Six months from now you will not remember whether ht was in cm or m.
  • No accented characters in object or file names. They work on most systems, but cause encoding problems when code moves between computers.
2a <- 10           # invalid: starts with a number
#> Error in parse(text = input): <text>:1:2: unexpected symbol
#> 1: 2a
#>      ^
yield_bags_ha
#> [1] 62.4
Yield_bags_ha   # a different name: R cannot find it
#> Error:
#> ! object 'Yield_bags_ha' not found

The message object 'Yield_bags_ha' not found is by far the most common one in daily work. Most of the time it is a typo or an object that has not yet been created in this session.

2.2.2 What assignment really does

Consider:

x <- 10
y <- x
x <- 20
y
#> [1] 10

y is still 10. The assignment y <- x does not create a “shortcut” to x; when x changes, R creates a new value and y keeps pointing at the old one. This rule (called copy-on-modify) makes R predictable: changing one object never changes another unless you ask it to.

2.3 Everything is a vector

There is no such thing as a “lone number” in R. The 62.4 we typed is a vector of length 1. Longer vectors are created with c() (for combine):

yield_bags_ha <- c(62.4, 58.1, 70.3, 66.0, 65.8)
length(yield_bags_ha)
#> [1] 5

The big advantage is that operations are vectorised: they apply to every element at once, without you having to write a loop.

yield_t_ha <- yield_bags_ha * bag_weight_kg / 1000
yield_t_ha
#> [1] 3.744 3.486 4.218 3.960 3.948

mean(yield_t_ha)
#> [1] 3.8712
max(yield_t_ha)
#> [1] 4.218
yield_t_ha > 3.9    # which plots went above 3.9 t/ha?
#> [1] FALSE FALSE  TRUE  TRUE  TRUE

2.3.1 The recycling rule

When two vectors of different lengths enter the same operation, the shorter one is repeated until it matches the longer:

c(1, 2, 3, 4) * c(10, 100)
#> [1]  10 200  30 400

This is useful (multiplying by a single number is recycling a vector of length 1), but also dangerous. If the longer length is not a multiple of the shorter, R warns you:

c(1, 2, 3, 4, 5) * c(10, 100)
#> Warning in c(1, 2, 3, 4, 5) * c(10, 100): longer object length is not a
#> multiple of shorter object length
#> [1]  10 200  30 400  50

This warning almost always signals a logic error, such as data missing from one block. Take it seriously.

2.4 Atomic types

Every vector has a type, and all its elements share that type. The four you will use all the time:

Type Example in the trial How to write it
logical did the plot lodge? TRUE, FALSE
integer days to maturity 118L (the L marks an integer)
double yield in bags/ha 62.4, 60
character cultivar name "SJ-04" (in quotes) 
lodging <- c(FALSE, FALSE, TRUE, FALSE, TRUE)
days_to_maturity <- c(118L, 121L, 125L, 119L, 123L)
cultivar <- c("SJ-01", "SJ-02", "SJ-03", "SJ-04", "SJ-05")

typeof(lodging)
#> [1] "logical"
typeof(days_to_maturity)
#> [1] "integer"
typeof(yield_bags_ha)
#> [1] "double"
typeof(cultivar)
#> [1] "character"

Notice that 60 is a double, not an integer. In R, numbers typed without the L suffix are always double. Together the two types form what R calls numeric:

typeof(60)
#> [1] "double"
typeof(60L)
#> [1] "integer"
is.numeric(60L)
#> [1] TRUE

There are also the complex and raw types, which rarely show up in breeding analyses.

2.5 Coercion: when R changes the type

Since a vector can only have one type, what happens when we mix types?

c(62.4, "SJ-01")
#> [1] "62.4"  "SJ-01"
c(TRUE, 2L)
#> [1] 1 2
c(1L, 2.5)
#> [1] 1.0 2.5

R converts everything to the most flexible type, following this hierarchy:

logical → integer → double → character

This is called implicit coercion. It has a very practical use: in numeric operations, TRUE becomes 1 and FALSE becomes 0. So counting and computing proportions of logical conditions is trivial:

sum(lodging)     # how many plots lodged?
#> [1] 2
mean(lodging)    # what proportion lodged?
#> [1] 0.4
sum(yield_bags_ha > 65)
#> [1] 3

2.5.1 Explicit coercion and the comma trap

The as.*() functions convert types on purpose:

as.character(days_to_maturity)
#> [1] "118" "121" "125" "119" "123"
as.integer("118")
#> [1] 118
as.integer(3.9)       # truncates, does not round!
#> [1] 3
round(3.9)
#> [1] 4

When the conversion is impossible, the result is NA with a warning. The classic case in Brazil is a number typed with a decimal comma:

as.numeric("62,4")
#> Warning: NAs introduced by coercion
#> [1] NA

The warning NAs introduced by coercion means “there was text that did not look like a number, and I replaced it with NA”. An immediate fix is to swap the comma for a point before converting:

as.numeric(sub(",", ".", "62,4"))
#> [1] 62.4

In lesson 5 we will solve this at import time, telling R about the Brazilian format, without touching the values one by one.

ImportantA column of numbers that “turned into” text

If a single cell of a yield column contains "62,4", "lost" or "-", the whole column is read as character, and mean() stops working. When a numeric calculation fails, the first question is: what is the type of this vector? typeof() and str() answer it.

2.6 Special values

2.6.1 NA: the missing value

NA (not available) represents a value that should exist but was not observed: a plot lost to hail, a plant that never flowered. It is contagious, and rightly so: if a value is unknown, any calculation involving it is unknown too.

yield_bags_ha <- c(62.4, 58.1, NA, 66.0, 65.8)

yield_bags_ha * 2
#> [1] 124.8 116.2    NA 132.0 131.6
mean(yield_bags_ha)
#> [1] NA

Most summary functions have an na.rm (NA remove) argument:

mean(yield_bags_ha, na.rm = TRUE)
#> [1] 63.075

Use na.rm = TRUE deliberately: the mean is now over 4 plots, not 5. In a trial, that can unbalance the comparison between cultivars.

To find the missing values, use is.na(), never == NA:

yield_bags_ha == NA      # always NA: "is it equal to an unknown value?"
#> [1] NA NA NA NA NA
is.na(yield_bags_ha)
#> [1] FALSE FALSE  TRUE FALSE FALSE
sum(is.na(yield_bags_ha))
#> [1] 1
which(is.na(yield_bags_ha))
#> [1] 3

NA has a type too. Most of the time this is invisible, but there are specific versions for when the type needs to be explicit:

typeof(NA)
#> [1] "logical"
typeof(NA_real_)
#> [1] "double"
typeof(NA_character_)
#> [1] "character"

2.6.2 NULL: the absence of an object

NULL is not a missing value: it is the absence of anything. It has length zero and disappears when combined:

length(NULL)
#> [1] 0
length(NA)
#> [1] 1
c(62.4, NULL, 58.1)
#> [1] 62.4 58.1
c(62.4, NA, 58.1)
#> [1] 62.4   NA 58.1

You will meet NULL as the result of functions that “returned nothing” and as the default value of optional arguments.

2.6.3 NaN and Inf: impossible or infinite results

0 / 0          # NaN: "not a number"
#> [1] NaN
1 / 0          # Inf
#> [1] Inf
log(0)         # -Inf
#> [1] -Inf
sqrt(-1)       # NaN, with a warning
#> Warning in sqrt(-1): NaNs produced
#> [1] NaN

NaN tends to appear when computing something like a variance from a single observation, or a ratio of zeros, for example a harvest index for a plot with no plants. To filter all these cases at once:

values <- c(1.2, NA, NaN, Inf, -Inf, 3.4)
is.na(values)       # NA and NaN
#> [1] FALSE  TRUE  TRUE FALSE FALSE FALSE
is.nan(values)      # only NaN
#> [1] FALSE FALSE  TRUE FALSE FALSE FALSE
is.finite(values)   # only the "ordinary" numbers
#> [1]  TRUE FALSE FALSE FALSE FALSE  TRUE
Value Meaning Length Test
NA exists, but is unknown 1 is.na()
NULL does not exist 0 is.null()
NaN undefined mathematical result 1 is.nan()
Inf, -Inf infinity 1 is.infinite()

2.7 Functions

Almost everything you do in R is calling functions. A call is the function name followed by parentheses holding the arguments:

round(66.04167, digits = 1)
#> [1] 66

2.7.1 Positional and named arguments

Arguments can be passed by position or by name. The two calls below are equivalent:

round(66.04167, 1)
#> [1] 66
round(digits = 1, x = 66.04167)
#> [1] 66

The lab rule of thumb: the first argument (usually the data) goes by position; the rest go by name. round(x, digits = 1) is clearer than round(x, 1), especially in functions with many arguments.

To see a function’s arguments and their default values:

args(round)
#> function (x, digits = 0, ...) 
#> NULL
args(seq)
#> function (...) 
#> NULL

The digits = 0 in round is a default value: if you do not supply it, it is used.

seq(from = 1, to = 25, by = 6)   # plot numbers every 6
#> [1]  1  7 13 19 25
seq_len(5)                       # 1 to 5, the safe way to create indices
#> [1] 1 2 3 4 5
rep(c("B1", "B2", "B3"), times = 2)
#> [1] "B1" "B2" "B3" "B1" "B2" "B3"
rep(c("B1", "B2", "B3"), each = 2)
#> [1] "B1" "B1" "B2" "B2" "B3" "B3"

2.7.2 Writing your first function

If you convert bags to tonnes more than twice, it is time to write a function:

bags_to_t <- function(bags, bag_weight_kg = 60) {
  bags * bag_weight_kg / 1000
}

bags_to_t(62.4)
#> [1] 3.744
bags_to_t(yield_bags_ha)
#> [1] 3.744 3.486    NA 3.960 3.948
bags_to_t(150, bag_weight_kg = 50)  # 50 kg bags
#> [1] 7.5

A function has three parts: the arguments (bags, and bag_weight_kg with default 60), the body between braces and the return value, which is the result of the last expression in the body. Because we only used vectorised operations, the function already works for a single value or a whole vector. In lesson 13 we will return to functions with input validation and custom error messages.

2.8 Getting help

Every R function has a documentation page:

?mean              # help for a function
help("mean")       # the same
??"standard deviation"   # topic search across all installed packages
example(mean)      # runs the examples from the help page

A help page always has the same sections. Read them in this order:

  1. Usage: how to call the function and which arguments have defaults.
  2. Arguments: what each argument accepts.
  3. Value: what the function returns (type and structure).
  4. Examples: the fastest way to understand the function. Copy, run and modify.

When the documentation is not enough, search for the exact error message, in quotes, in a search engine or on Posit Community. Very often someone has already had the same problem.

2.9 How to read an error message

R communicates through three kinds of condition, in increasing order of severity:

Condition What it means Does the code continue?
message information yes
warning something looks off, but there is a result yes
error impossible to continue no

In the console, an error almost always looks like Error in <call> : <reason>, or simply Error: <reason> when the failure happens at the top level. The call tells you where it happened and the reason tells you why.

In this book, messages appear in a two-line format, the same one used by tidyverse packages: the first line says where (Error in ...) and the second, starting with !, says why. You read it the same way. Here are the most common errors:

"62.4" + 1
#> Error in `"62.4" + 1`:
#> ! non-numeric argument to binary operator

non-numeric argument to binary operator: one side of + is text. Ask typeof() about each side.

average(yield_bags_ha)
#> Error in `average()`:
#> ! could not find function "average"

could not find function "average": no function exists with that name (it is mean), or it belongs to a package that has not been loaded.

mean(cultivar)
#> Warning in mean.default(cultivar): argument is not numeric or logical:
#> returning NA
#> [1] NA

There was no error here, but a warning: mean() received text and returned NA. Warnings like this are worse than errors, because the code carries on with a meaningless result.

round(62.4, digits = 1
#> Error in parse(text = input): <text>:2:0: unexpected end of input
#> 1: round(62.4, digits = 1
#>    ^

Syntax errors (a parenthesis that never closes, an extra comma) appear before the code runs. In the console, an open parenthesis turns the prompt from > into +, waiting for the rest of the command; press Esc to cancel.

The tidyverse packages, which we will use from lesson 4 onwards, add to the two-line format further lines starting with ℹ or ✖, which give context and often suggest the fix. It pays to read them to the end.

TipA routine for any error
  1. Read the whole message, slowly, ideally out loud.
  2. Identify which call failed and which object is involved.
  3. Inspect that object: typeof(), length(), str(), head().
  4. Shrink the problem: run only the failing line, with a minimal example.
  5. Only then search for the message online.

2.10 Under the hood

2.10.1 Everything is a function call

Even operators are functions. 2 + 3 is a convenient way of writing a call to the function `+`:

`+`(2, 3)
#> [1] 5
`[`(cultivar, 2)
#> [1] "SJ-02"

That explains why the error from "62.4" + 1 talks about a binary operator: the + function received two arguments (it is binary) and one of them was not numeric.

2.10.2 Integers have a limit

Integers take 32 bits, so there is a largest possible integer:

.Machine$integer.max
#> [1] 2147483647
.Machine$integer.max + 1L
#> Warning in .Machine$integer.max + 1L: NAs produced by integer overflow
#> [1] NA

The result is NA with an overflow warning. This can happen when multiplying large counts (number of markers × number of individuals). double has no such problem at the same scale, which is why R uses double by default.

2.10.3 Attributes

Vectors can carry attributes, metadata that do not change the values. The most common one is names:

names(yield_bags_ha) <- cultivar
yield_bags_ha
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 
#>  62.4  58.1    NA  66.0  65.8
yield_bags_ha["SJ-04"]
#> SJ-04 
#>    66
attributes(yield_bags_ha)
#> $names
#> [1] "SJ-01" "SJ-02" "SJ-03" "SJ-04" "SJ-05"

Factors, matrices and data frames, which we will meet in the next lesson, are vectors with special attributes. Understanding this demystifies much of R’s behaviour.

2.11 Exercises

  1. Unit conversion. A soybean trial yielded c(55.2, 61.7, 48.9, 72.1) bags per hectare. Convert to kg/ha and to t/ha, and compute the mean in t/ha rounded to two decimal places.
TipSolution 
bags_ha <- c(55.2, 61.7, 48.9, 72.1)
kg_ha <- bags_ha * 60
t_ha <- kg_ha / 1000
kg_ha
#> [1] 3312 3702 2934 4326
round(mean(t_ha), digits = 2)
#> [1] 3.57
  1. Predicting types. Without running the code, predict the type of each vector. Then check with typeof().
c(1, TRUE, FALSE)
c("1", 2, 3)
c(1L, NA)
c(1.5, NA, 3L)
TipSolution 
typeof(c(1, TRUE, FALSE))   # double: the logical is promoted to double
#> [1] "double"
typeof(c("1", 2, 3))        # character: one string pulls everything to text
#> [1] "character"
typeof(c(1L, NA))           # integer: NA adapts to its neighbours' type
#> [1] "integer"
typeof(c(1.5, NA, 3L))      # double
#> [1] "double"
  1. Missing values. For height_cm <- c(98, 102, NA, 95, NA, 110), compute: the number of plants measured, the mean height of the measured plants and the positions of the plants without a measurement.
TipSolution 
height_cm <- c(98, 102, NA, 95, NA, 110)
sum(!is.na(height_cm))
#> [1] 4
mean(height_cm, na.rm = TRUE)
#> [1] 101.25
which(is.na(height_cm))
#> [1] 3 5

The ! operator negates logical values: !is.na() means “is not missing”.

  1. The comma spreadsheet. You received the vector weight_100_seeds <- c("15,2", "16,8", "14,9", "-", "17,1"). Convert it to numbers so that "-" becomes NA, and compute the mean. Why does a warning appear, and why is it acceptable here?
TipSolution 
weight_100_seeds <- c("15,2", "16,8", "14,9", "-", "17,1")
weight_num <- as.numeric(sub(",", ".", weight_100_seeds))
#> Warning: NAs introduced by coercion
weight_num
#> [1] 15.2 16.8 14.9   NA 17.1
mean(weight_num, na.rm = TRUE)
#> [1] 16

The warning NAs introduced by coercion appears because "-" cannot be converted. It is acceptable because we know "-" was how the spreadsheet marked a lost sample. In production code, make this explicit by replacing "-" with NA before converting; that way an unexpected warning will still catch your attention.

  1. Your own function. Write a function kg_ha_to_bags(kg, bag_weight_kg = 60) that does the reverse of bags_to_t(), starting from kg/ha. Test it with c(3600, 4200) and with 50 kg bags.
TipSolution 
kg_ha_to_bags <- function(kg, bag_weight_kg = 60) {
  kg / bag_weight_kg
}

kg_ha_to_bags(c(3600, 4200))
#> [1] 60 70
kg_ha_to_bags(c(3600, 4200), bag_weight_kg = 50)
#> [1] 72 84

Summary

  • Use <- to assign and = for arguments; names in snake_case, descriptive and with units.
  • Everything in R is a vector, and operations are vectorised. Watch out for recycling warnings.
  • The main atomic types are logical, integer, double and character; when mixed, R converts to the most flexible one.
  • NA is unknown and contagious; NULL is absence; NaN and Inf come from impossible or infinite calculations. Test with is.na(), never with == NA.
  • Compare decimals with all.equal(), not with ==.
  • When facing an error: read it, identify the call and the object, inspect the type, shrink the problem.
