6  Transformação com dplyr I

Objetivos da aula

Ao final desta aula você será capaz de:

  1. Selecionar linhas (filter) e colunas (select) de uma tabela com condições claras.
  2. Criar e modificar colunas (mutate), inclusive com classificações por faixas (case_when).
  3. Ordenar (arrange) e resumir (summarise) dados.
  4. Fazer qualquer operação por grupo (local, híbrido, bloco) com .by ou group_by().
  5. Encadear tudo com o pipe para responder perguntas reais sobre um ensaio multiambiente.

6.2 A gramática do dplyr

NotaIntenção do pacote: dplyr

Problema que resolve. Manipular tabelas com o R base exige combinar [, $, subset(), aggregate(), tapply() e order(), cada um com sua lógica. O código resultante é difícil de ler e de modificar.

Filosofia. O dplyr oferece um pequeno conjunto de verbos, cada um com uma única responsabilidade, que recebem uma tabela como primeiro argumento e devolvem uma tabela. Dentro dos verbos, as colunas são referidas pelo nome, sem aspas e sem $. Combinados com o pipe, os verbos formam frases que se leem como a descrição da análise: “pegue o ensaio, filtre Londrina, agrupe por híbrido, resuma a produtividade”.

Por que ele e não as alternativas. O R base resolve tudo, mas com mais esforço de leitura. O data.table é mais rápido e conciso, à custa de uma sintaxe mais densa; vamos conhecê-lo na aula 18. O dplyr também funciona como interface para bancos de dados e para o duckdb, então o mesmo código serve para tabelas que não cabem na memória.

Os verbos que veremos hoje:

Verbo Atua em O que faz
filter() linhas mantém as linhas que atendem a condições
select() colunas escolhe, remove ou renomeia colunas
mutate() colunas cria ou modifica colunas
arrange() linhas ordena as linhas
summarise() grupos reduz cada grupo a uma linha de resumo

Todos seguem as mesmas regras: o primeiro argumento é a tabela, os seguintes descrevem o que fazer usando os nomes das colunas, e o resultado é sempre uma nova tabela. A tabela original nunca é modificada; para guardar o resultado, atribua-o a um objeto.

AvisoDuas armadilhas do filter()
  1. = não é ==. filter(local = "Londrina") dá erro, e a mensagem do dplyr até sugere a correção. Leia-a.
  2. filter() descarta linhas em que a condição dá NA. filter(prod_kg_ha < 8000) não devolve as parcelas perdidas, porque NA < 8000 é NA, e não TRUE. Se você quiser mantê-las, diga explicitamente: filter(prod_kg_ha < 8000 | is.na(prod_kg_ha)).

6.5.1 Classificações: if_else() e case_when()

Para duas categorias, if_else(condição, valor_se_verdadeiro, valor_se_falso):

milho |>
  mutate(perdida = if_else(is.na(prod_kg_ha), "sim", "não")) |>
  count(perdida)
#> # A tibble: 2 × 2
#>   perdida     n
#>   <chr>   <int>
#> 1 não       233
#> 2 sim         7

Para várias faixas, case_when() avalia as condições em ordem e usa a primeira verdadeira:

milho <- milho |>
  mutate(
    ciclo = case_when(
      florescimento_dias <= 60 ~ "precoce",
      florescimento_dias <= 64 ~ "medio",
      florescimento_dias > 64  ~ "tardio",
      .default = NA_character_
    )
  )

count(milho, ciclo)
#> # A tibble: 3 × 2
#>   ciclo       n
#>   <chr>   <int>
#> 1 medio     107
#> 2 precoce    56
#> 3 tardio     77

Como as condições são avaliadas em ordem, a segunda (<= 64) só alcança quem não entrou na primeira, ou seja, os de 61 a 64 dias. O .default define o valor quando nenhuma condição é verdadeira.

Repare que desta vez guardamos o resultado em milho: a coluna ciclo estará disponível no restante da aula.

    n_perdidas = sum(is.na(prod_kg_ha)),
    media_kg_ha = mean(prod_kg_ha, na.rm = TRUE),
    dp_kg_ha = sd(prod_kg_ha, na.rm = TRUE),
    cv_pct = 100 * dp_kg_ha / media_kg_ha
  )

#> 1        240          7       9464.    1109.   11.7

n() conta as linhas. O coeficiente de variação (cv_pct) usa colunas criadas no próprio summarise(), como no mutate().

Um resumo do ensaio inteiro é útil, mas o que o melhorista quer saber é o desempenho por local e por híbrido.

6.8.1 group_by(): a forma tradicional

Você verá muito código com group_by() seguido de summarise(). O resultado é o mesmo:

milho |>
  group_by(local) |>
  summarise(media_kg_ha = mean(prod_kg_ha, na.rm = TRUE))
#> # A tibble: 4 × 2
#>   local       media_kg_ha
#>   <chr>             <dbl>
#> 1 Londrina          9194.
#> 2 Rio Verde        10295.
#> 3 Sete Lagoas       9532.
#> 4 Viçosa            8816.

A diferença é que group_by() cria uma tabela agrupada, que continua agrupada nas etapas seguintes até que você chame ungroup(). Isso é útil em cadeias longas, mas é fonte de erros quando você esquece o agrupamento ativo. O padrão do laboratório é .by para operações pontuais e group_by() apenas quando várias etapas seguidas usam o mesmo agrupamento.

6.8.2 mutate() por grupo: desempenho relativo

Em ensaios multiambiente, comparar produtividades brutas entre locais mistura o efeito do híbrido com o do ambiente. Um primeiro passo é expressar cada parcela em relação à média do seu local:

milho |>
  mutate(
    media_local = mean(prod_kg_ha, na.rm = TRUE),
    desvio_local = prod_kg_ha - media_local,
    relativo_pct = 100 * prod_kg_ha / media_local,
    .by = local
  ) |>
  select(local, hibrido, bloco, prod_kg_ha, media_local, relativo_pct) |>
  arrange(desc(relativo_pct))

6.11 Por baixo do capô

6.11.1 Por que o dplyr entende nomes sem aspas

Em filter(milho, prod_kg_ha > 9000), prod_kg_ha não é um objeto do ambiente global:

prod_kg_ha
#> Error:
#> ! object 'prod_kg_ha' not found

O dplyr procura os nomes primeiro nas colunas da tabela e só depois no ambiente. Esse mecanismo, chamado de data masking, é o que torna o código tão legível. Ele tem uma consequência: se existir uma coluna e um objeto com o mesmo nome, a coluna vence. Para usar o objeto, marque-o com .env$:

limite <- 10000
milho |> filter(prod_kg_ha > limite) |> nrow()
#> [1] 69

prod_kg_ha <- 0   # um objeto com o mesmo nome de uma coluna
milho |> filter(prod_kg_ha > .env$prod_kg_ha) |> nrow()   # compara com o objeto (0): todas as não perdidas
#> [1] 233
rm(prod_kg_ha)

Na aula 16 veremos como escrever funções que usam o dplyr, onde esse mecanismo exige alguns cuidados extras.

6.11.2 O que é uma tabela agrupada

agrupado <- group_by(milho, local)
class(agrupado)
#> [1] "grouped_df" "tbl_df"     "tbl"        "data.frame"
group_vars(agrupado)
#> [1] "local"
n_groups(agrupado)
#> [1] 4

Um grouped_df é um tibble com um atributo extra que guarda quais linhas pertencem a cada grupo. A impressão mostra # Groups: local [4]; fique atento a essa linha.

6.11.3 O equivalente em R base

# dplyr
milho |> filter(local == "Londrina") |> summarise(m = mean(prod_kg_ha, na.rm = TRUE))
#> # A tibble: 1 × 1
#>       m
#>   <dbl>
#> 1 9194.

# R base
mean(milho$prod_kg_ha[milho$local == "Londrina"], na.rm = TRUE)
#> [1] 9193.691
tapply(milho$prod_kg_ha, milho$local, mean, na.rm = TRUE)

#>    9193.691   10294.650    9532.224    8815.800

Para um cálculo isolado, o R base é perfeitamente adequado. A vantagem do dplyr aparece quando as etapas se acumulam.

Resumo

  • Os verbos do dplyr recebem uma tabela, usam os nomes das colunas sem aspas e devolvem uma nova tabela.
  • filter() escolhe linhas e descarta NA nas condições; select() escolhe colunas com auxiliares como starts_with() e where().
  • mutate() cria colunas; case_when() classifica em faixas, avaliando as condições em ordem.
  • arrange() ordena; summarise() reduz a um resumo.
  • .by aplica qualquer verbo por grupo: summarise() devolve uma linha por grupo, mutate() mantém todas as linhas.
