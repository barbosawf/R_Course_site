Objetivos da aula

Ao final desta aula você será capaz de:

3.1 O mapa das estruturas

Na aula anterior vimos que todo dado no R vive dentro de um vetor de um tipo só. As estruturas desta aula são formas de organizar esses vetores. Duas perguntas definem qual usar:

Todos os elementos do mesmo tipo Elementos de tipos diferentes
Uma dimensão vetor atômico lista
Duas dimensões matriz data.frame / tibble

Uma matriz de genótipos SNP (todos números 0, 1 ou 2) é homogênea e bidimensional: matriz. Uma planilha de ensaio com cultivar (texto), bloco (inteiro) e produtividade (decimal) é heterogênea e bidimensional: data.frame. A saída de um modelo, com coeficientes, resíduos e a fórmula usada, é heterogênea e de formato livre: lista.

3.2 Vetores: selecionando elementos

Vamos usar a produtividade de seis cultivares de soja em sacas por hectare:

produtividade <- c(62.4, 58.1, 70.3, 66.0, 65.8, 54.9)
names(produtividade) <- c("SJ-01", "SJ-02", "SJ-03", "SJ-04", "SJ-05", "SJ-06")
produtividade
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  62.4  58.1  70.3  66.0  65.8  54.9

O operador [ seleciona elementos. Há quatro formas de indicar quais:

# 1. Por posição (o R começa a contar em 1, não em 0)
produtividade[3]
#> SJ-03 
#>  70.3
produtividade[c(1, 3, 5)]
#> SJ-01 SJ-03 SJ-05 
#>  62.4  70.3  65.8
produtividade[2:4]
#> SJ-02 SJ-03 SJ-04 
#>  58.1  70.3  66.0

# 2. Por exclusão: índices negativos removem elementos
produtividade[-1]
#> SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  58.1  70.3  66.0  65.8  54.9
produtividade[-c(1, 2)]
#> SJ-03 SJ-04 SJ-05 SJ-06 
#>  70.3  66.0  65.8  54.9

# 3. Por nome
produtividade["SJ-04"]
#> SJ-04 
#>    66
produtividade[c("SJ-01", "SJ-06")]
#> SJ-01 SJ-06 
#>  62.4  54.9

# 4. Por condição lógica: o vetor lógico funciona como um filtro
produtividade[produtividade > 65]
#> SJ-03 SJ-04 SJ-05 
#>  70.3  66.0  65.8

A quarta forma é a mais poderosa e a que você mais usará. Vale entender o que acontece em duas etapas:

produtividade > 65                 # primeiro, um vetor lógico do mesmo tamanho
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#> FALSE FALSE  TRUE  TRUE  TRUE FALSE
produtividade[produtividade > 65]  # depois, ficam só as posições TRUE
#> SJ-03 SJ-04 SJ-05 
#>  70.3  66.0  65.8

Condições podem ser combinadas com & (e), | (ou) e ! (não):

produtividade[produtividade > 60 & produtividade < 68]
#> SJ-01 SJ-04 SJ-05 
#>  62.4  66.0  65.8
produtividade[!(names(produtividade) %in% c("SJ-01", "SJ-02"))]
#> SJ-03 SJ-04 SJ-05 SJ-06 
#>  70.3  66.0  65.8  54.9

O operador %in% pergunta “este elemento está neste conjunto?” e é indispensável para filtrar listas de cultivares ou de marcadores.

Para saber onde estão os elementos que atendem a uma condição, use which():

which(produtividade > 65)
#> SJ-03 SJ-04 SJ-05 
#>     3     4     5
which.max(produtividade)
#> SJ-03 
#>     3

3.2.1 O que acontece fora dos limites

produtividade[10]
#> <NA> 
#>   NA

Pedir uma posição que não existe não gera erro: gera NA. Esse comportamento silencioso é um bom motivo para conferir length() antes de indexar por posição.

3.2.2 Modificando elementos

A mesma sintaxe serve para substituir valores:

produtividade["SJ-02"] <- 59.0
produtividade[produtividade < 56] <- NA   # marca um valor suspeito como faltante
produtividade
#> SJ-01 SJ-02 SJ-03 SJ-04 SJ-05 SJ-06 
#>  62.4  59.0  70.3  66.0  65.8    NA

3.3 Fatores: variáveis categóricas

Bloco, local, cultivar e classe de resistência são categorias, não textos livres. O R tem uma estrutura específica para isso, o fator:

bloco <- factor(c(1, 2, 3, 1, 2, 3, 1, 2, 3))
bloco
#> [1] 1 2 3 1 2 3 1 2 3
#> Levels: 1 2 3
levels(bloco)
#> [1] "1" "2" "3"
nlevels(bloco)
#> [1] 3
table(bloco)
#> bloco
#> 1 2 3 
#> 3 3 3

Um fator guarda dois componentes: os níveis (as categorias possíveis) e, para cada observação, a qual nível ela pertence. Isso traz três vantagens:

  1. Modelos estatísticos tratam fatores como categorias. Se bloco fosse numérico, lm() estimaria uma inclinação para “bloco”, o que não faz sentido. Como fator, estima um efeito para cada bloco.
  2. Os níveis definem a ordem em tabelas e gráficos.
  3. Níveis sem observações continuam existindo, o que é útil para mostrar que uma categoria ficou vazia.

3.3.1 Ordem dos níveis e fatores ordenados

Por padrão, os níveis ficam em ordem alfabética. Quando a ordem tem significado, informe-a:

reacao <- c("suscetivel", "resistente", "moderada", "resistente", "suscetivel")

factor(reacao)   # ordem alfabética: moderada, resistente, suscetivel
#> [1] suscetivel resistente moderada   resistente suscetivel
#> Levels: moderada resistente suscetivel

reacao_f <- factor(
  reacao,
  levels = c("resistente", "moderada", "suscetivel"),
  ordered = TRUE
)
reacao_f
#> [1] suscetivel resistente moderada   resistente suscetivel
#> Levels: resistente < moderada < suscetivel
reacao_f < "suscetivel"   # comparações só fazem sentido em fatores ordenados
#> [1] FALSE  TRUE  TRUE  TRUE FALSE

Valores que não estão entre os níveis viram NA, sem erro. Atenção a erros de digitação:

factor(c("resistente", "Resistente"), levels = c("resistente", "moderada", "suscetivel"))
#> [1] resistente <NA>      
#> Levels: resistente moderada suscetivel

3.3.2 A armadilha: transformar fator em número

Por dentro, um fator é um vetor de inteiros com um rótulo para cada inteiro. Isso gera um dos erros mais traiçoeiros do R:

dose_kg_ha <- factor(c("60", "90", "120", "60", "120"))
as.numeric(dose_kg_ha)     # errado! são os códigos internos dos níveis
#> [1] 2 3 1 2 1

Os níveis estão em ordem alfabética ("120", "60", "90"), então o R devolveu 1, 2 e 3 em vez das doses. A forma correta passa pelo texto:

as.numeric(as.character(dose_kg_ha))
#> [1]  60  90 120  60 120

Na aula 8 conheceremos o pacote forcats, que torna a manipulação de fatores (reordenar, renomear, agrupar níveis) muito mais clara.

3.4 Matrizes

Uma matriz é um vetor atômico organizado em linhas e colunas. O exemplo clássico em genética é a matriz de marcadores: cada linha um indivíduo, cada coluna um SNP, e cada célula o número de cópias do alelo de referência (0, 1 ou 2).

marcadores <- matrix(
  c(0, 1, 2, 1, 0,
    1, 1, 2, 0, 0,
    2, 1, 1, 0, 1,
    0, 2, 2, 1, 0),
  nrow = 4,
  byrow = TRUE,
  dimnames = list(
    c("HB01", "HB02", "HB03", "HB04"),
    c("snp1", "snp2", "snp3", "snp4", "snp5")
  )
)
marcadores
#>      snp1 snp2 snp3 snp4 snp5
#> HB01    0    1    2    1    0
#> HB02    1    1    2    0    0
#> HB03    2    1    1    0    1
#> HB04    0    2    2    1    0
dim(marcadores)
#> [1] 4 5

O argumento byrow = TRUE preenche a matriz linha por linha, que é a ordem em que escrevemos os valores. Sem ele, o R preencheria coluna por coluna.

A indexação usa [linha, coluna]; deixar uma posição vazia significa “todas”:

marcadores["HB02", ]          # todos os SNPs do HB02
#> snp1 snp2 snp3 snp4 snp5 
#>    1    1    2    0    0
marcadores[, "snp3"]          # o snp3 em todos os híbridos
#> HB01 HB02 HB03 HB04 
#>    2    2    1    2
marcadores[1:2, c("snp1", "snp5")]
#>      snp1 snp5
#> HB01    0    0
#> HB02    1    0

Operações aritméticas continuam vetorizadas, e há funções próprias para linhas e colunas:

# Frequência do alelo de referência em cada SNP
colMeans(marcadores) / 2
#>  snp1  snp2  snp3  snp4  snp5 
#> 0.375 0.625 0.875 0.250 0.125

# Número de locos heterozigotos (valor 1) em cada híbrido
rowSums(marcadores == 1)
#> HB01 HB02 HB03 HB04 
#>    2    2    3    1

3.4.1 O drop silencioso

Ao selecionar uma única coluna, a matriz “desmonta” e vira vetor:

marcadores[, "snp3"]
#> HB01 HB02 HB03 HB04 
#>    2    2    1    2
marcadores[, "snp3", drop = FALSE]
#>      snp3
#> HB01    2
#> HB02    2
#> HB03    1
#> HB04    2

Quando você escreve uma função que deve sempre receber uma matriz, use drop = FALSE. Esse comportamento é uma fonte comum de erros em código de genética, quando um filtro de qualidade deixa por acaso um único marcador.

Voltaremos às matrizes a fundo na aula 27 (álgebra matricial) e no Módulo 5 (matrizes de parentesco). Para ir além de duas dimensões existem os arrays (array()), úteis, por exemplo, para guardar uma matriz de marcadores por cromossomo.

3.5 Listas

Uma lista é um vetor em que cada elemento pode ser qualquer coisa: um número, um texto, um vetor, uma matriz, outra lista. É a estrutura mais flexível do R:

ensaio <- list(
  nome = "Ensaio de cultivares de soja",
  locais = c("Viçosa", "Rio Verde"),
  n_blocos = 4L,
  marcadores = marcadores
)
str(ensaio)
#> List of 4
#>  $ nome      : chr "Ensaio de cultivares de soja"
#>  $ locais    : chr [1:2] "Viçosa" "Rio Verde"
#>  $ n_blocos  : int 4
#>  $ marcadores: num [1:4, 1:5] 0 1 2 0 1 1 1 2 2 2 ...
#>   ..- attr(*, "dimnames")=List of 2
#>   .. ..$ : chr [1:4] "HB01" "HB02" "HB03" "HB04"
#>   .. ..$ : chr [1:5] "snp1" "snp2" "snp3" "snp4" ...

str() (de structure) é a melhor forma de enxergar uma lista: mostra o nome, o tipo e o início do conteúdo de cada elemento.

3.5.1 [, [[ e $

Esta é a distinção mais importante da aula. Pense na lista como uma caixa de amostras com compartimentos etiquetados:

  • [ devolve uma caixa menor, ainda uma lista, contendo os compartimentos escolhidos.
  • [[ abre o compartimento e devolve o conteúdo.
  • $ é um atalho para [[ com o nome escrito diretamente.
ensaio["locais"]        # uma lista com um elemento
#> $locais
#> [1] "Viçosa"    "Rio Verde"
class(ensaio["locais"])
#> [1] "list"

ensaio[["locais"]]      # o vetor de texto em si
#> [1] "Viçosa"    "Rio Verde"
class(ensaio[["locais"]])
#> [1] "character"

ensaio$locais           # o mesmo que ensaio[["locais"]]
#> [1] "Viçosa"    "Rio Verde"

A diferença aparece quando você tenta usar o resultado:

length(ensaio["locais"])     # 1: a "caixa" tem um compartimento
#> [1] 1
length(ensaio[["locais"]])   # 2: o vetor tem dois locais
#> [1] 2
ensaio["n_blocos"] * 2       # erro: não dá para multiplicar uma lista
#> Error in `ensaio["n_blocos"] * 2`:
#> ! non-numeric argument to binary operator
ensaio[["n_blocos"]] * 2
#> [1] 8

Também é possível encadear as seleções para chegar a algo dentro de um elemento:

ensaio$locais[2]
#> [1] "Rio Verde"
ensaio$marcadores["HB03", "snp1"]
#> [1] 2

3.5.2 Por que listas importam

Você raramente criará listas complexas à mão, mas vai recebê-las o tempo todo. Quase toda função de modelagem devolve uma lista:

modelo <- lm(dist ~ speed, data = cars)
typeof(modelo)
#> [1] "list"
names(modelo)
#>  [1] "coefficients"  "residuals"     "effects"       "rank"         
#>  [5] "fitted.values" "assign"        "qr"            "df.residual"  
#>  [9] "xlevels"       "call"          "terms"         "model"
modelo$coefficients
#> (Intercept)       speed 
#>  -17.579095    3.932409

No Módulo 2, o pacote purrr fará das listas uma ferramenta central: ajustaremos um modelo por ambiente e guardaremos todos em uma lista.

3.6 Tabelas: data.frame

Um data.frame é a estrutura das planilhas: cada coluna é um vetor (com seu próprio tipo) e todas as colunas têm o mesmo comprimento.

soja <- data.frame(
  cultivar = c("SJ-01", "SJ-02", "SJ-03", "SJ-04"),
  bloco = factor(c(1, 1, 2, 2)),
  produtividade_sc_ha = c(62.4, 58.1, 70.3, 66.0),
  acamamento = c(FALSE, FALSE, TRUE, FALSE)
)
soja
#>   cultivar bloco produtividade_sc_ha acamamento
#> 1    SJ-01     1                62.4      FALSE
#> 2    SJ-02     1                58.1      FALSE
#> 3    SJ-03     2                70.3       TRUE
#> 4    SJ-04     2                66.0      FALSE

Funções de inspeção que você usará em todo conjunto de dados novo:

str(soja)
#> 'data.frame':    4 obs. of  4 variables:
#>  $ cultivar           : chr  "SJ-01" "SJ-02" "SJ-03" "SJ-04"
#>  $ bloco              : Factor w/ 2 levels "1","2": 1 1 2 2
#>  $ produtividade_sc_ha: num  62.4 58.1 70.3 66
#>  $ acamamento         : logi  FALSE FALSE TRUE FALSE
nrow(soja)
#> [1] 4
ncol(soja)
#> [1] 4
names(soja)
#> [1] "cultivar"            "bloco"               "produtividade_sc_ha"
#> [4] "acamamento"
summary(soja)
#>       cultivar bloco produtividade_sc_ha acamamento     
#>  Length   :4   1:2   Min.   :58.10       Mode :logical  
#>  N.unique :4   2:2   1st Qu.:61.33       FALSE:3

A indexação combina o que vimos em matrizes e listas:

soja$produtividade_sc_ha                  # uma coluna, como vetor
#> [1] 62.4 58.1 70.3 66.0
soja[["cultivar"]]                        # idem
#> [1] "SJ-01" "SJ-02" "SJ-03" "SJ-04"
soja[soja$produtividade_sc_ha > 60, ]     # linhas que atendem a uma condição
#>   cultivar bloco produtividade_sc_ha acamamento
#> 1    SJ-01     1                62.4      FALSE
#> 3    SJ-03     2                70.3       TRUE
#> 4    SJ-04     2                66.0      FALSE
soja[, c("cultivar", "acamamento")]       # algumas colunas
#>   cultivar acamamento
#> 1    SJ-01      FALSE
#> 2    SJ-02      FALSE
#> 3    SJ-03       TRUE
#> 4    SJ-04      FALSE
soja$produtividade_t_ha <- soja$produtividade_sc_ha * 60 / 1000  # nova coluna
soja

#> 2    SJ-02     1                58.1      FALSE              3.486
#> 3    SJ-03     2                70.3       TRUE              4.218
#> 4    SJ-04     2                66.0      FALSE              3.960

A partir da aula 6, faremos essas operações com o dplyr, que é mais legível. Mas é importante conhecer a forma base: você a encontrará em código antigo, em pacotes e em respostas na internet.

3.6.1 As pegadinhas do data.frame

O data.frame tem comportamentos herdados de décadas atrás que surpreendem quem começa:

soja[, "cultivar"]       # selecionou uma coluna... e devolveu um vetor, não uma tabela
#> [1] "SJ-01" "SJ-02" "SJ-03" "SJ-04"
soja$acam                # completou o nome "acam" para "acamamento" sem avisar!
#> [1] FALSE FALSE  TRUE FALSE

O segundo caso, chamado de partial matching, é perigoso: se você digitar errado o nome de uma coluna, o R pode devolver outra coluna sem dizer nada.

3.7 Tabelas modernas: tibble

NotaIntenção do pacote: tibble

Problema que resolve. Os comportamentos surpreendentes do data.frame (conversão silenciosa em vetor, partial matching, impressão de milhares de linhas no console) fazem bugs passarem despercebidos.

Filosofia. Um tibble é um data.frame mais cauteloso: faz menos coisas por conta própria e avisa mais cedo quando algo parece errado. Ele não muda tipos, não completa nomes, não cria nomes de linha e imprime só o que cabe na tela, mostrando o tipo de cada coluna.

Por que ele e não as alternativas. Um tibble continua sendo um data.frame: qualquer função que aceita um data.frame aceita um tibble. Ganhamos segurança sem perder compatibilidade. É também o formato devolvido por todos os pacotes do tidyverse (readr, dplyr, tidyr), então adotá-lo desde já evita converter de um lado para o outro. A alternativa data.table é excelente para dados muito grandes e será vista na aula 18, mas tem uma sintaxe própria que preferimos apresentar depois.

library(tibble)

soja_tb <- tibble(
  cultivar = c("SJ-01", "SJ-02", "SJ-03", "SJ-04"),
  bloco = factor(c(1, 1, 2, 2)),
  produtividade_sc_ha = c(62.4, 58.1, 70.3, 66.0),
  produtividade_t_ha = produtividade_sc_ha * 60 / 1000   # usa uma coluna recém-criada
)
soja_tb
#> # A tibble: 4 × 4
#>   cultivar bloco produtividade_sc_ha produtividade_t_ha
#>   <chr>    <fct>               <dbl>              <dbl>
#> 1 SJ-01    1                    62.4               3.74
#> 2 SJ-02    1                    58.1               3.49
#> 3 SJ-03    2                    70.3               4.22
#> 4 SJ-04    2                    66                 3.96

Repare na impressão: as dimensões (4 × 4) e, abaixo de cada nome, o tipo da coluna (<chr>, <fct>, <dbl>). Compare as pegadinhas:

soja_tb[, "cultivar"]    # continua sendo um tibble
#> # A tibble: 4 × 1
#>   cultivar
#>   <chr>   
#> 1 SJ-01   
#> 2 SJ-02   
#> 3 SJ-03   
#> 4 SJ-04
soja_tb$prod             # NULL e um aviso, em vez de adivinhar a coluna
#> Warning: Unknown or uninitialised column: `prod`.
#> NULL

Para digitar pequenas tabelas no código, tribble() permite escrever linha por linha, o que fica muito mais legível:

locais <- tribble(
  ~local,        ~uf,  ~altitude_m,
  "Viçosa",      "MG", 650,
  "Rio Verde",   "GO", 750,
  "Londrina",    "PR", 585
)
locais
#> # A tibble: 3 × 3
#>   local     uf    altitude_m
#>   <chr>     <chr>      <dbl>
#> 1 Viçosa    MG           650
#> 2 Rio Verde GO           750
#> 3 Londrina  PR           585

E as_tibble() converte um data.frame existente:

as_tibble(soja)
#> # A tibble: 4 × 5
#>   cultivar bloco produtividade_sc_ha acamamento produtividade_t_ha
#>   <chr>    <fct>               <dbl> <lgl>                   <dbl>
#> 1 SJ-01    1                    62.4 FALSE                    3.74
#> 2 SJ-02    1                    58.1 FALSE                    3.49
#> 3 SJ-03    2                    70.3 TRUE                     4.22
#> 4 SJ-04    2                    66   FALSE                    3.96

3.8 Por baixo do capô

3.8.1 Um data.frame é uma lista

typeof(soja)
#> [1] "list"
is.list(soja)
#> [1] TRUE
length(soja)     # o número de colunas!
#> [1] 5

Um data.frame é uma lista de vetores de mesmo comprimento, com os atributos names, row.names e class. Por isso soja[["cultivar"]] e soja$cultivar funcionam: são operações de lista.

attributes(soja)
#> $names
#> [1] "cultivar"            "bloco"               "produtividade_sc_ha"
#> [4] "acamamento"          "produtividade_t_ha" 
#> 
#> $row.names
#> [1] 1 2 3 4
#> 
#> $class
#> [1] "data.frame"

3.8.3 Uma matriz é um vetor com dimensões

v <- 1:6
dim(v) <- c(2, 3)
v
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6

Atribuir o atributo dim a um vetor transforma-o em matriz. Esse padrão (estruturas complexas como vetores simples mais atributos) explica boa parte da consistência do R.

3.9 Exercícios

  1. Seleção em vetores. Com o vetor altura_cm <- c(HB01 = 212, HB02 = 230, HB03 = 198, HB04 = 241, HB05 = 225), selecione: (a) a altura do HB03; (b) todas menos a do HB01; (c) os híbridos com altura acima de 220 cm; (d) o nome do híbrido mais alto.
DicaSolução 
altura_cm <- c(HB01 = 212, HB02 = 230, HB03 = 198, HB04 = 241, HB05 = 225)
altura_cm["HB03"]
#> HB03 
#>  198
altura_cm[-1]
#> HB02 HB03 HB04 HB05 
#>  230  198  241  225
altura_cm[altura_cm > 220]
#> HB02 HB04 HB05 
#>  230  241  225
names(which.max(altura_cm))
#> [1] "HB04"
  1. Fatores. Crie um fator ordenado com as notas de severidade de doença c("baixa", "alta", "media", "baixa", "alta", "alta"), com os níveis em ordem crescente de severidade. Conte quantas parcelas há em cada nível e quantas têm severidade maior que “baixa”.
DicaSolução 
severidade <- factor(
  c("baixa", "alta", "media", "baixa", "alta", "alta"),
  levels = c("baixa", "media", "alta"),
  ordered = TRUE
)
table(severidade)
#> severidade
#> baixa media  alta 
#>     2     1     3
sum(severidade > "baixa")
#> [1] 4
  1. Matriz de marcadores. Usando a matriz marcadores desta aula, calcule para cada SNP a frequência do alelo de referência e identifique os SNPs com frequência entre 0,2 e 0,8. Selecione a submatriz só com esses SNPs, garantindo que o resultado seja uma matriz.
DicaSolução 
freq <- colMeans(marcadores) / 2
freq
#>  snp1  snp2  snp3  snp4  snp5 
#> 0.375 0.625 0.875 0.250 0.125
selecionados <- names(freq)[freq >= 0.2 & freq <= 0.8]
marcadores[, selecionados, drop = FALSE]
#>      snp1 snp2 snp4
#> HB01    0    1    1
#> HB02    1    1    0
#> HB03    2    1    0
#> HB04    0    2    1
  1. Listas. A partir da lista ensaio, extraia: (a) o número de blocos multiplicado pelo número de locais; (b) o genótipo do HB04 no snp2. Explique por que ensaio["n_blocos"] * length(ensaio["locais"]) não dá o resultado esperado.
DicaSolução 
ensaio$n_blocos * length(ensaio$locais)
#> [1] 8
ensaio$marcadores["HB04", "snp2"]
#> [1] 2

ensaio["n_blocos"] é uma lista, e listas não aceitam aritmética (erro). E length(ensaio["locais"]) é 1, o número de elementos da sublista, e não 2, o número de locais.

  1. De data.frame a tibble. Crie um tibble com 3 híbridos (HB01 a HB03), seus florescimentos em dias (61, 64, 59) e uma coluna precoce que seja TRUE quando o florescimento for menor que 62 dias, criada a partir da coluna de florescimento dentro do próprio tibble().
DicaSolução 
tibble(
  hibrido = c("HB01", "HB02", "HB03"),
  florescimento_dias = c(61, 64, 59),
  precoce = florescimento_dias < 62
)

#> 2 HB02                    64 FALSE  
#> 3 HB03                    59 TRUE

Resumo

  • Vetores e matrizes são homogêneos; listas e data.frames aceitam tipos diferentes.
  • Selecione por posição, exclusão, nome ou condição lógica; %in% e which() completam o kit.
  • Fatores representam categorias; defina a ordem dos níveis e nunca converta um fator direto em número.
  • Em listas, [ devolve uma sublista e [[/$ devolvem o conteúdo.
  • Use drop = FALSE quando o resultado precisar continuar sendo uma matriz ou tabela.
  • Prefira tibble a data.frame: mesma compatibilidade, menos surpresas.
