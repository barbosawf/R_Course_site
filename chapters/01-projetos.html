1  Projetos: a unidade de trabalho no R

“Se o primeiro comando do seu script é setwd(), eu vou até o seu computador e coloco fogo nele.” Paráfrase bem-humorada de Jenny Bryan (Bryan 2017)

Objetivos da aula

Ao final desta aula você será capaz de:

  1. Explicar por que, no laboratório, todo trabalho em R acontece dentro de um projeto e não em scripts soltos.
  2. Criar um projeto do RStudio pelo menu e pelo código, com a estrutura de pastas padrão do QGSL Lab.
  3. Distinguir caminhos absolutos de relativos e entender o papel do diretório de trabalho.
  4. Ler um arquivo de dados de forma reprodutível com o pacote here.
  5. Diagnosticar o erro mais comum de quem começa: cannot open file ... No such file or directory.
  6. Configurar o RStudio para sempre começar com uma sessão limpa.
NotaRoteiro da aula ao vivo (60 min)
Tempo Atividade

5–15 O problema dos scripts soltos: setwd() e o diretório de trabalho

30–45 Caminhos com here e o primeiro arquivo de dados; o erro “cannot open file”

1.1 Preparando o ambiente

1.1.1 O que precisa estar instalado

Usaremos quatro ferramentas durante todo o curso. Cada uma tem um papel diferente:

Ferramenta Papel Onde obter
R A linguagem e o interpretador que executa o código https://cran.r-project.org
RStudio O ambiente de desenvolvimento (IDE): editor, console, gerenciador de arquivos e projetos https://posit.co/download/rstudio-desktop/
Quarto O sistema de publicação que transforma texto + código em relatórios, livros e sites (este livro é feito em Quarto) Já vem com o RStudio; também em https://quarto.org
Git O controle de versões, que registra o histórico de cada arquivo do projeto https://git-scm.com

Uma distinção importante: R e RStudio não são a mesma coisa. O R é o motor; o RStudio é o painel do carro. Você pode usar R sem RStudio (pelo terminal ou por outros editores, como o VS Code ou o Positron), mas não pode usar o RStudio sem R.

Para conferir o que está instalado, execute no console:

R.version.string            # versão do R
RStudio.Version()$version   # versão do RStudio (só funciona dentro do RStudio)
quarto::quarto_version()    # versão do Quarto
system("git --version")     # versão do Git
R.version.string
#> [1] "R version 4.6.1 (2026-06-24)"
AvisoMantenha o R atualizado

Pacotes novos frequentemente exigem versões recentes do R. Uma regra prática para o laboratório: atualize o R pelo menos uma vez por ano, logo após o lançamento da versão x.y.0 (normalmente em abril), e reinstale os pacotes em seguida.

1.1.2 Um passeio pelo RStudio

Ao abrir o RStudio você verá quatro painéis:

  1. Editor (superior esquerdo): onde você escreve e salva scripts (.R) e documentos Quarto (.qmd). É aqui que o trabalho de verdade acontece.
  2. Console (inferior esquerdo): onde o R executa os comandos. Ótimo para testes rápidos, péssimo para guardar trabalho, porque nada do que você digita ali fica salvo de forma organizada.
  3. Environment / History / Git (superior direito): mostra os objetos que existem na memória da sessão, o histórico de comandos e, depois que ativarmos o Git, o estado dos arquivos.
  4. Files / Plots / Packages / Help / Viewer (inferior direito): navegador de arquivos, gráficos, pacotes instalados e documentação.

Dois atalhos que você usará centenas de vezes por aula:

Atalho O que faz
Ctrl + Enter (Cmd + Enter no Mac) Executa a linha atual (ou a seleção) do editor no console
Ctrl + Shift + F10 Reinicia a sessão do R (veremos por que isso é importante)

1.2 O problema: scripts soltos

Imagine que um colega do laboratório lhe envia este script para analisar um ensaio de milho:

rm(list = ls())
setwd("C:/Users/joao/Desktop/doutorado/analises/milho_2025")

dados <- read.csv("ensaio_milho_piloto.csv")
mean(dados$produtividade_t_ha)

Esse script parece inofensivo, mas ele tem dois problemas graves:

  1. setwd() com um caminho absoluto. O caminho C:/Users/joao/Desktop/... só existe no computador do João. No seu computador, no servidor do laboratório ou no computador do João daqui a dois anos (depois de uma formatação), o script falha na segunda linha.
  2. rm(list = ls()) dá uma falsa sensação de limpeza. Essa linha apaga os objetos do Environment, mas não descarrega pacotes, não restaura opções alteradas com options() e não desfaz mudanças em variáveis de ambiente. O script pode funcionar na sua sessão “suja” e falhar na sessão de outra pessoa.

1.2.1 O diretório de trabalho

Para entender o primeiro problema precisamos de um conceito: o diretório de trabalho (working directory). É a pasta a partir da qual o R interpreta qualquer caminho relativo. Você pode consultá-lo com getwd():

getwd()
#> [1] "/home/ana/projetos/R_Course"

Quando você escreve read.csv("ensaio_milho_piloto.csv"), o R procura o arquivo dentro do diretório de trabalho. Se o arquivo estiver em outra pasta, o R não o encontra. O setwd() muda o diretório de trabalho, e por isso parece a solução. Mas ele amarra o script a uma máquina específica.

A pergunta certa não é “como faço o R encontrar a minha pasta?”, e sim “como faço para que qualquer pessoa, em qualquer computador, rode meu código sem editar nada?”. A resposta é o projeto.

1.3 A solução: projetos do RStudio

Um projeto do RStudio é uma pasta que contém um arquivo .Rproj. Ao abrir esse arquivo (com dois cliques ou pelo menu File > Open Project), o RStudio:

  • inicia uma sessão nova do R;
  • define o diretório de trabalho como a pasta do projeto, automaticamente;
  • mantém histórico, abas abertas e configurações separados para cada projeto.

Com isso, todos os caminhos do código podem ser escritos relativos à raiz do projeto, e o mesmo código funciona em qualquer computador que tenha uma cópia da pasta.

ImportanteRegra do laboratório

No QGSL Lab, toda análise vive dentro de um projeto. Uma pergunta de pesquisa, um artigo, uma tese ou um curso: cada um é um projeto, com sua própria pasta, seu .Rproj e seu repositório Git. Scripts soltos na área de trabalho não são aceitos em revisões de código.

1.3.1 Criando um projeto pelo menu

  1. File > New Project…
  2. Escolha New Directory > New Project.
  3. Dê um nome sem espaços e sem acentos (por exemplo, ensaio_milho_2025) e escolha onde a pasta será criada.
  4. Marque Create a git repository (vamos usá-lo a partir da aula 9).
  5. Clique em Create Project.

O RStudio reinicia dentro do novo projeto. Repare que o nome do projeto aparece no canto superior direito da janela.

1.3.2 Criando um projeto pelo código: o pacote usethis

NotaIntenção do pacote: usethis

Problema que resolve. Tarefas de configuração de projetos (criar a estrutura, ativar o Git, configurar o GitHub, adicionar licença, criar arquivos padrão) são repetitivas e fáceis de errar quando feitas à mão.

Filosofia. O usethis automatiza essas tarefas com funções de nome autoexplicativo (use_git(), use_readme_md(), create_project()), sempre informando o que fez e o que você ainda precisa fazer. Ele faz parte do conjunto de ferramentas de desenvolvimento mantido pela equipe do tidyverse (junto com devtools, roxygen2 e testthat).

Por que ele e não as alternativas. A alternativa é clicar nos menus do RStudio ou criar pastas e arquivos manualmente. O menu funciona bem para um projeto; o usethis vence quando queremos padronizar dezenas de projetos do laboratório e documentar a configuração em código, que é reprodutível por definição. Voltaremos a ele na aula 9 (Git e GitHub) e no apêndice sobre a criação do pacote do laboratório.

A função usethis::create_project() cria a pasta, o arquivo .Rproj e um .gitignore básico, e em seguida abre o projeto novo no RStudio. Vamos usá-la para criar o projeto do ensaio piloto de milho. Todo o restante desta aula será feito de dentro desse projeto, exatamente como você trabalhará nas suas próprias análises.

1.4 Mão na massa: o projeto do ensaio de milho

1.4.1 Passo 1: criar o projeto dentro de Documentos

Vamos criar o projeto ensaio_milho_2025 dentro da sua pasta Documentos. O caminho dessa pasta muda de um sistema operacional para outro:

Sistema Pasta Documentos
macOS ~/Documents (ou seja, /Users/seu_usuario/Documents)
Linux Ubuntu ~/Documents, ou ~/Documentos se o sistema foi instalado em português
Windows C:/Users/seu_usuario/Documents

No console do RStudio, rode apenas a linha do seu sistema:

usethis::create_project("~/Documents/ensaio_milho_2025")                      # macOS e Linux
usethis::create_project("~/Documentos/ensaio_milho_2025")                     # Linux em português
usethis::create_project("C:/Users/seu_usuario/Documents/ensaio_milho_2025")   # Windows (troque seu_usuario)

Se preferir, deixe o R descobrir onde fica a sua pasta Documentos. Sys.info()[["sysname"]] devolve "Darwin" no macOS, "Linux" no Linux e "Windows" no Windows; no Linux, o comando xdg-user-dir informa o nome da pasta no idioma do sistema:

pasta_documentos <- switch(
  Sys.info()[["sysname"]],
  Darwin  = "~/Documents",
  Linux   = system("xdg-user-dir DOCUMENTS", intern = TRUE),
  Windows = file.path(Sys.getenv("USERPROFILE"), "Documents")
)

usethis::create_project(file.path(pasta_documentos, "ensaio_milho_2025"))

O RStudio abre uma nova sessão, já dentro do projeto: o nome ensaio_milho_2025 aparece no canto superior direito e o painel Files mostra a pasta do projeto. Os objetos que você tinha criado antes ficaram na sessão anterior; daqui em diante, todo código desta aula deve ser digitado nessa nova sessão. Confira:

getwd()
#> [1] "/home/ana/Documents/ensaio_milho_2025"
fs::dir_tree(all = TRUE)
#> .
#> ├── .gitignore
#> ├── R
#> └── ensaio_milho_2025.Rproj

Repare em três detalhes:

  • ensaio_milho_2025.Rproj é o arquivo que marca a pasta como projeto. Da próxima vez, basta dar dois cliques nele para voltar ao projeto.
  • .gitignore lista arquivos que o Git deve ignorar (por exemplo, .Rhistory e .RData).
  • A pasta R/ é criada por padrão; no laboratório ela guarda funções reutilizáveis, enquanto análises vão em scripts/.

O operador :: (como em usethis::create_project) chama uma função de um pacote sem carregá-lo inteiro com library(). Usaremos essa forma sempre que uma função de um pacote aparecer uma única vez, porque ela deixa explícito de onde a função vem.

1.4.2 Passo 2: a estrutura de pastas do laboratório

Toda análise do QGSL Lab segue a mesma estrutura. Ainda no console do projeto novo, crie as pastas:

pastas <- c(
  "data/raw",        # dados brutos, exatamente como vieram do campo ou do laboratório
  "data/processed",  # dados limpos, gerados pelos scripts
  "scripts",         # análises, numeradas na ordem de execução
  "R",               # funções reutilizáveis
  "output/figures",  # gráficos gerados
  "output/tables",   # tabelas geradas
  "reports"          # relatórios Quarto
)

fs::dir_create(pastas)
fs::dir_tree()
#> .
#> ├── R
#> ├── data
#> │   ├── processed
#> │   └── raw
#> ├── ensaio_milho_2025.Rproj
#> ├── output
#> │   ├── figures
#> │   └── tables
#> ├── reports
#> └── scripts

Repare que os caminhos são relativos: fs::dir_create("data/raw") cria a pasta dentro do diretório de trabalho, que é a raiz do projeto. O próprio repositório deste curso segue a mesma estrutura, com uma pasta chapters/ no lugar de reports/.

Três regras dão sentido a essa estrutura:

  1. Dados brutos são somente leitura. Nunca edite um arquivo em data/raw/ à mão, nem pelo Excel. Toda correção é feita por código, que grava o resultado em data/processed/. Assim, qualquer correção fica documentada e pode ser refeita.
  2. Tudo em data/processed/ e output/ pode ser apagado e recriado executando os scripts. Se não puder, algum passo da análise não está no código.
  3. Scripts são numerados na ordem de execução: A01_importar.R, A02_limpar.R, A03_modelar.R. Quem chega ao projeto sabe por onde começar. A letra antes do número é uma convenção do laboratório: o nome de um script nunca começa com número, e o prefixo A01_, A02_… mantém a ordem de execução na listagem de arquivos.

1.4.3 Passo 3: colocar os dados em data/raw/

Baixe o arquivo do ensaio piloto: ensaio_milho_piloto.csv (clique com o botão direito e escolha Salvar link como, se o navegador abrir o arquivo em vez de baixá-lo).

O navegador salva o arquivo na sua pasta de downloads, que não faz parte do projeto. Ele precisa ir para data/raw/. Você pode arrastá-lo pelo gerenciador de arquivos ou, melhor ainda, mover pelo R, a partir do console do projeto:

file.copy(
  from = "~/Downloads/ensaio_milho_piloto.csv",   # onde o navegador salvou
  to = "data/raw/"                                 # para dentro do projeto
)
#> [1] TRUE

list.files("data/raw")
#> [1] "ensaio_milho_piloto.csv"

No Windows, a pasta de downloads é C:/Users/seu_usuario/Downloads. Se file.copy() devolver FALSE, o arquivo não foi encontrado no caminho de origem: confira o nome e a pasta com list.files("~/Downloads").

1.5 Caminhos de arquivos

1.5.1 Absolutos e relativos

Um caminho absoluto começa na raiz do sistema de arquivos e identifica o arquivo sem ambiguidade, mas só naquela máquina:

/home/ana/projetos/R_Course/data/raw/ensaio_milho_piloto.csv    # Linux
/Users/ana/projetos/R_Course/data/raw/ensaio_milho_piloto.csv   # macOS
C:/Users/ana/projetos/R_Course/data/raw/ensaio_milho_piloto.csv # Windows

Um caminho relativo descreve onde o arquivo está a partir do diretório de trabalho:

data/raw/ensaio_milho_piloto.csv

Dentro de um projeto, o diretório de trabalho é a raiz do projeto, então o caminho relativo funciona em qualquer computador.

DicaUse sempre a barra /

O R aceita a barra normal / em todos os sistemas, inclusive no Windows. A barra invertida \ precisa ser duplicada dentro de textos ("C:\\Users"), porque ela tem significado especial em strings. Use / e evite o problema.

1.5.2 Montando caminhos com file.path()

Em vez de colar pedaços de texto, use file.path(), que insere o separador correto:

file.path("data", "raw", "ensaio_milho_piloto.csv")
#> [1] "data/raw/ensaio_milho_piloto.csv"

1.5.3 O pacote here

Ainda resta um problema sutil. O diretório de trabalho nem sempre é a raiz do projeto. Quando o Quarto renderiza um relatório, por exemplo, o diretório de trabalho passa a ser a pasta do relatório. Se o seu relatório estiver em reports/, durante a renderização o caminho relativo data/raw/ensaio_milho_piloto.csv não existiria (o R o procuraria em reports/data/raw/).

NotaIntenção do pacote: here

Problema que resolve. Construir caminhos que apontem sempre para o mesmo lugar, independentemente de onde o código é executado (console, script, documento Quarto em subpasta, servidor), sem setwd() e sem caminhos absolutos.

Filosofia. O here encontra a raiz do projeto procurando, a partir do diretório atual e subindo pelas pastas-mãe, por arquivos que marcam um projeto (um .Rproj, uma pasta .git, um arquivo .here, entre outros). A função here() devolve caminhos a partir dessa raiz. Ele é deliberadamente minúsculo: faz uma coisa só, e bem.

Por que ele e não as alternativas.

  • setwd(): amarra o código a um computador; descartado pelas razões vistas acima.
  • Caminhos relativos simples: funcionam no console, mas quebram quando o diretório de trabalho muda (como em documentos Quarto em subpastas).
  • rprojroot: é o motor por trás do here, mais flexível porém mais verboso. O here oferece a mesma robustez com uma interface de uma função só.

1.5.4 Passo 4: ler os dados de dentro do projeto

No console do projeto ensaio_milho_2025, carregue o here:

library(here)
#> here() starts at /home/ana/Documents/ensaio_milho_2025

A mensagem here() starts at ... mostra qual pasta o here reconheceu como raiz. Confira sempre essa linha quando abrir um projeto novo.

Para montar o caminho do arquivo de dados, passe cada pedaço como um argumento:

caminho_dados <- here("data", "raw", "ensaio_milho_piloto.csv")
file.exists(caminho_dados)
#> [1] TRUE

E agora lemos o arquivo. Na aula 5 conheceremos o pacote readr e suas vantagens; por enquanto, usamos a função read.csv() que já vem com o R:

ensaio <- read.csv(here("data", "raw", "ensaio_milho_piloto.csv"))

head(ensaio)

#> 3    HB01     3               8.64              201
#> 4    HB02     1               9.04              213

Esse código funciona igualmente no console, em um script em scripts/ e em um relatório em reports/, em qualquer computador que tenha uma cópia do projeto. É exatamente o que queríamos. (Este livro também é um projeto com a mesma estrutura, e é por isso que os resultados mostrados aqui são os mesmos que você obtém no seu.)

Algumas perguntas rápidas ao nosso ensaio piloto:

1.6 Errando de propósito: “cannot open file”

O erro mais comum de quem começa no R é este:

read.csv("ensaio_milho_piloto.csv")
#> Warning in file(file, "rt"): cannot open file 'ensaio_milho_piloto.csv': No
#> such file or directory
#> Error in `file()`:
#> ! cannot open the connection

Leia a mensagem com calma. Ela diz duas coisas:

  • cannot open file 'ensaio_milho_piloto.csv': o R não conseguiu abrir o arquivo com esse caminho.
  • No such file or directory: o motivo é que, a partir do diretório de trabalho atual, não existe arquivo com esse nome.

Um roteiro de diagnóstico que resolve quase todos os casos:

# 1. Onde o R está procurando?
getwd()
#> [1] "/home/ana/Documents/ensaio_milho_2025"

# 2. O arquivo existe onde eu acho que existe?
file.exists(here("data", "raw", "ensaio_milho_piloto.csv"))
#> [1] TRUE

# 3. O que realmente há na pasta? (erros de digitação e extensões aparecem aqui)
list.files(here("data", "raw"))
#> [1] "ensaio_milho_piloto.csv"

O arquivo existe e está no lugar certo: o problema é que read.csv("ensaio_milho_piloto.csv") o procurou na raiz do projeto, e não em data/raw/.

As causas mais frequentes, em ordem:

  1. O caminho está relativo ao lugar errado (falta o here() ou a pasta data/raw).
  2. Erro de digitação no nome ou na extensão (.csv × .CSV × .xlsx). Em Linux e macOS, maiúsculas e minúsculas importam.
  3. O projeto não está aberto, e o diretório de trabalho é a pasta pessoal do usuário.
  4. O arquivo ficou na pasta de downloads e nunca foi movido para data/raw/.

1.7 Sessão limpa: nunca salve o .RData

Por padrão, ao fechar o RStudio aparece a pergunta Save workspace image to ~/.RData?. Se você responder “sim”, todos os objetos da sessão são salvos e reaparecem silenciosamente da próxima vez. Isso parece conveniente, mas é a principal fonte de análises que “funcionam no meu computador”: o resultado depende de objetos que nenhum script cria.

A regra do laboratório é: o código é a fonte da verdade, não a sessão. Qualquer objeto deve poder ser recriado executando os scripts do começo ao fim, em uma sessão nova.

Configure isso uma vez, para sempre:

  • No RStudio: Tools > Global Options > General, desmarque Restore .RData into workspace at startup e escolha Never em Save workspace to .RData on exit.
  • Ou, pelo código:
usethis::use_blank_slate()

E adote o hábito: antes de considerar uma análise pronta, reinicie a sessão (Ctrl + Shift + F10) e execute o script inteiro. Se funcionar, está reprodutível.

1.8 Organizando um script

Um script do laboratório tem sempre a mesma anatomia. Este é um exemplo que você pode salvar como scripts/A01_explorar_piloto.R no projeto ensaio_milho_2025 (File > New File > R Script, e salve na pasta scripts/):

# Exploração inicial do ensaio piloto de milho ---------------------------------
# Autor: Seu Nome
# Objetivo: verificar a leitura dos dados e calcular resumos básicos.

# Pacotes ----------------------------------------------------------------------
library(here)

# Dados ------------------------------------------------------------------------
ensaio <- read.csv(here("data", "raw", "ensaio_milho_piloto.csv"))

# Resumos ----------------------------------------------------------------------
mean(ensaio$produtividade_t_ha)
tapply(ensaio$produtividade_t_ha, ensaio$hibrido, mean)
  • O cabeçalho diz o que o script faz e por quê.
  • Os pacotes são carregados no topo, todos juntos. Quem lê sabe de imediato do que o script depende.
  • Linhas terminadas em ---- criam seções navegáveis no RStudio (Ctrl + Shift + R insere uma). Use o menu de seções no rodapé do editor para pular entre elas.
  • Não há setwd() nem rm(list = ls()).

1.9 Por baixo do capô

1.9.1 O que há dentro de um .Rproj

O arquivo .Rproj é um arquivo de texto simples com as opções do projeto. Como o diretório de trabalho é a raiz do projeto, basta o nome do arquivo:

readLines("ensaio_milho_2025.Rproj")
#>  [1] "Version: 1.0"                 ""                            
#>  [3] "RestoreWorkspace: No"         "SaveWorkspace: No"           
#>  [5] "AlwaysSaveHistory: Default"   ""                            
#>  [7] "EnableCodeIndexing: Yes"      "Encoding: UTF-8"             
#>  [9] ""                             "AutoAppendNewline: Yes"      
#> [11] "StripTrailingWhitespace: Yes" "LineEndingConversion: Posix" 
#> [13] ""

O RStudio usa essas opções (por exemplo, RestoreWorkspace: No) e cria ao lado uma pasta oculta .Rproj.user/ com o estado da interface (abas abertas, histórico). Essa pasta é pessoal e nunca vai para o Git.

1.9.2 Como o here encontra a raiz

O here sobe pela árvore de pastas a partir do diretório de trabalho até encontrar um marcador de projeto. A função dr_here() explica o raciocínio:

here::dr_here()
#> here() starts at /home/ana/Documents/ensaio_milho_2025.
#> - This directory contains a file matching "[.]Rproj$" with contents matching
#>   "^Version: " in the first line
#> - Initial working directory: /home/ana/Documents/ensaio_milho_2025/reports
#> - Current working directory: /home/ana/Documents/ensaio_milho_2025/reports

Nesse exemplo, dr_here() foi chamado durante a renderização de um relatório em reports/: o diretório de trabalho era reports/, e mesmo assim o here encontrou a raiz pelo .Rproj. A raiz é determinada uma única vez, quando o pacote é carregado. Por isso, se você trocar de projeto, reinicie a sessão.

1.9.3 Por que rm(list = ls()) não basta

library(here)
rm(list = ls())
search()   # o pacote "here" continua carregado na sessão
#>  [1] ".GlobalEnv"        "package:here"      "package:stats"  ...

ls() lista apenas os objetos do ambiente global. Pacotes carregados, opções e variáveis de ambiente sobrevivem. A única limpeza verdadeira é reiniciar a sessão.

1.9.4 O til ~ e o caminho pessoal

O til ~ é um atalho para a sua pasta pessoal. path.expand() mostra para onde ele aponta:

path.expand("~/projetos")
#> [1] "/home/ana/projetos"

Ele é útil no console para abrir projetos, mas também é um caminho específico de usuário e não deve aparecer dentro de scripts de análise.

1.10 Exercícios

  1. Seu primeiro projeto. Crie, pelo menu do RStudio, um projeto chamado curso_r_exercicios e, dentro dele, as pastas data/raw, data/processed, scripts e R. Confira o resultado no painel Files.
DicaSolução

Depois de criar o projeto pelo menu (File > New Project > New Directory > New Project), execute no console do novo projeto:

fs::dir_create(c("data/raw", "data/processed", "scripts", "R"))

Como o diretório de trabalho é a raiz do projeto, os caminhos relativos já apontam para o lugar certo.

  1. Conserte o script do João. Reescreva o script abaixo para que ele funcione em qualquer computador, supondo que o arquivo está em data/raw/ dentro do projeto.
rm(list = ls())
setwd("C:/Users/joao/Desktop/doutorado/analises/milho_2025")
dados <- read.csv("ensaio_milho_piloto.csv")
mean(dados$produtividade_t_ha)
DicaSolução 
library(here)

dados <- read.csv(here("data", "raw", "ensaio_milho_piloto.csv"))
mean(dados$produtividade_t_ha)

Removemos rm(list = ls()) (substituído pelo hábito de reiniciar a sessão) e setwd() (substituído pelo projeto + here).

  1. Diagnóstico. Execute read.csv(here("data", "raw", "ensaio_milho_piloto.CSV")), com a extensão em maiúsculas. O que acontece no seu sistema operacional? Use list.files() para descobrir o nome correto.
DicaSolução

Em Linux e macOS (com o sistema de arquivos padrão sensível a maiúsculas) o R retorna cannot open file ... No such file or directory, porque .CSV e .csv são nomes diferentes. No Windows a leitura funciona, porque o sistema de arquivos não diferencia maiúsculas de minúsculas. É mais um motivo para escrever os nomes exatamente como estão no disco: o código precisa rodar em qualquer sistema.

list.files(here("data", "raw"))
#> [1] "ensaio_milho_piloto.csv"
  1. Produtividade por híbrido. Usando tapply(), calcule a produtividade média de cada híbrido do ensaio piloto e descubra qual híbrido foi o mais produtivo. (Dica: sort() e which.max().)
DicaSolução 
medias <- tapply(ensaio$produtividade_t_ha, ensaio$hibrido, mean)
sort(medias, decreasing = TRUE)
#>     HB09     HB05     HB03     HB04     HB01     HB12     HB02     HB08 
#> 9.660000 9.636667 9.536667 9.403333 9.370000 9.186667 8.966667 8.916667 
#>     HB10     HB11     HB07     HB06 
#> 8.833333 8.786667 8.716667 7.720000
names(which.max(medias))
#> [1] "HB09"

Na aula 6 faremos o mesmo cálculo com dplyr::summarise(), de forma mais legível e extensível.

Resumo

  • Todo trabalho em R no laboratório acontece dentro de um projeto (.Rproj), que define o diretório de trabalho automaticamente.
  • Nunca use setwd() nem caminhos absolutos em scripts. Use caminhos relativos à raiz do projeto, construídos com here().
  • Estrutura padrão: data/raw (somente leitura), data/processed, scripts, R, output, reports.
  • O erro cannot open file ... No such file or directory se diagnostica com getwd(), file.exists() e list.files().
  • O código é a fonte da verdade. Não salve o .RData; reinicie a sessão e rode tudo de novo para conferir a reprodutibilidade.
